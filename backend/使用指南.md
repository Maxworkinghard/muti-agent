# 使用指南

这些人物在网页的「理性讨论」模式里使用：你选人物，再给每个人物挑一个性格，引擎就会让他们轮流发言、互相回应，最后由主持人做总结。

## 一、准备（只做一次）

1. 在 frontend/ 里把 .env.example 复制一份，改名为 .env.local，填上 ROUNDTABLE_API_KEY。模型地址和模型名有默认值，要换就改 ROUNDTABLE_API_BASE_URL、ROUNDTABLE_MODEL，兼容 OpenAI 接口的服务都能用。

   .env.local 里有密钥，不要发给别人；它已经被 git 忽略，不会提交到仓库。

2. 在 frontend/ 里运行 npm install。

## 二、跑一场讨论

1. 在 frontend/ 里运行 npm run dev，打开 http://localhost:5173 。
2. 选「理性讨论」模式。讨论主题可以先填，也可以不填。
3. 下一步选 2 到 5 个人物，每人选一个性格。这一页还可以改轮数（2 到 6 轮，第 1 轮开场、最后一轮收尾）和每次发言的字数上限（50 到 400 字）。
4. 进入对话后，对全体说第一句话，讨论就开始了。没填主题时，这句话就是议题；填了主题时，它作为补充说明一起交给大家。
5. 讨论中可以插话：先点某个人再说，就是单独问他；不点人就是对大家说，由目前说得最少的人来回应。

只想看界面、不想花额度，网址后面加 ?engine=mock，发言由模拟引擎生成，不调用模型。

每场讨论结束后，完整记录保存在本文件夹的 讨论记录/年月日-时分秒.json，格式见第七部分。

## 三、可以选什么

人物决定知道什么、从哪个角度看问题：

| 人物 | 角色 | 看问题的角度 |
|---|---|---|
| 老苏 | 追问者 | 关键词的定义是否清楚 |
| 阿澜 | 直觉派 | 具体例子和图像，推到无穷会怎样 |
| K | 逻辑家 | 论证的每一步是否成立 |
| 灰先生 | 怀疑者 | 我们凭什么知道 |
| 南姐 | 现实派 | 对具体的人有什么影响 |

性格决定讨论时的做法和说话的语气，每人选 1 个：温和狡猾、轻快好奇、冷静较真、冷幽默、直率温暖、老派学究、毒舌、热血。

人物没有默认性格，任何人物都能配任何性格。同一个人物换个性格，看问题的角度不变，说话方式会明显不同。每个性格的具体含义见 性格库/性格.json。

搭配建议：

- 一场 3 到 4 人效果最好，人太多时每人能说的话就少了。
- 让人物之间有反差，比如一个“热血”配一个“毒舌”，讨论会更有来回。
- 同一场里尽量不要让两个人用同一个性格，否则读起来分不清是谁在说。

## 四、讨论是怎么进行的

- 第 1 轮是开场，每个人从自己的角度切入问题，不急着给答案。
- 中间几轮是交锋，引擎会优先让被别人质疑的人先回应，其余的人接着补充或反驳。
- 最后一轮是收尾，每个人说明自己目前的立场，以及哪些地方被说服了。
- 结束后主持人写一份总结：各方观点、达成的共识、还没解决的分歧。

每条发言除了正文，还会标出在回应谁、立场（同意、部分同意、反对、提问、开场）、有没有提出新观点、向谁提出了质疑。

你插的话也会记进讨论里：被点名的人（没点名时是说得最少的人）先回应你，再把它接回议题。

## 五、只想拿提示词，自己调模型

    python 组装提示词.py 老苏 --性格 温和狡猾 --字数 150

这条命令会打印出这个人物的完整系统提示词，加 -o 文件名.md 可以保存到文件。在代码里调用的写法是：

    from 组装提示词 import build
    system_prompt = build("老苏", "温和狡猾", max_chars=150)

## 六、增加或修改人物

1. 照着 人物模板.json 填一个新文件，放进 人物/理性/。
2. 运行 python 校验.py，检查格式是否正确。
3. 运行 python 生成提示词.py，重新生成 提示词/ 下的文件。

修改性格库或已有人物之后，也要运行第 3 步。改完刷新网页就生效，不用重启 npm run dev。

## 七、讨论记录的格式

- question：议题；brief：开场时的补充说明（填了主题时才有）
- model：使用的模型
- members：[{name, role, personality}]
- rounds、maxChars：轮数、每次发言的字数上限
- log：发言列表，每条包括：
  - round：第几轮
  - name：发言人；你插的话记为“用户”
  - speech：发言正文
  - respondsTo：回应的是谁
  - stance：立场，取值为 同意 / 部分同意 / 反对 / 提问 / 开场，你的插话为 插话；模型输出无法解析时为 未知
  - newPoint：这次有没有提出新观点
  - challenge、challengeTarget：向谁提出了什么质疑
  - answered：这次回应了谁对自己的质疑
- summary：主持人最后的总结

## 八、常见问题

- 选人页提示“读不到人格数据库”：确认是在 frontend/ 里用 npm run dev 启动的，并且本文件夹下的 人物/、性格库/、提示词/ 都在。
- 选人页顶部提示没有配置 ROUNDTABLE_API_KEY：在 frontend/.env.local 里填好 key，再重启 npm run dev。
- 讨论中断，提示调用模型失败：网络或模型服务出了问题。每次调用会自动重试 3 次，一直失败就检查 ROUNDTABLE_API_BASE_URL、ROUNDTABLE_MODEL 和 key 是否正确。
- 提示人物或性格不存在：人物 JSON 里的名字改过，或者性格库里没有这个性格。改完记得运行第六部分的第 3 步。
- 运行 Python 小工具时中文显示乱码：Windows 上加 -X utf8，例如 python -X utf8 校验.py。
