## 1. 信息级别与使用规则

- **[观察]**：画面中可以看到的光照、结构、色彩和构图事实。
- **[候选偏好]**：根据用户选用这一组参考图推测的共同吸引点，须由用户确认。
- **[待确认]**：图片无法证明的偏好或尚未指定的取舍。
- **[用户已确认]**：用户本人直接表达认可的审美维度。室内方向见第 3 节，室外环境要求及未来场景差异化原则见第 4 节；不能将这些确认扩大解释为指定色号、照度、家具形制、植物数量、各场景最终外景、整个房间布局或最终美术验收。
- 图片中的某一特点值得借鉴，**不代表**用户想复刻整幅画面，尤其不代表喜欢原图中的 UI、字幕、战斗内容或建筑用途。
- 图片是视觉参考；除用户明确确认的审美要求外，具体形式、组合与落地方案仍为候选，不能当作 Three.js 已有实现或可直接复制的 Minecraft shader / 模组资源。

## 4. 用户已确认的室外环境审美要求（2026-10-09）

**确认来源**：用户提供本节 O01–O04 四张室外图，并明确提出以下五项要求。这些是用户已确认的审美要求，不能继续仅标为助手推测或候选偏好；各图的具体构图、季节和元素组合仍不等于某个场景的最终方案。

1. **自然、精致、有空间深度的室外风景。** 用户喜欢参考图中丰富的地形、植被、水体、天空和光影层次；室外环境应呈现自然的空间关系与精致的细节。
2. **不同 3D 场景必须有不同的外景设计。** 不能所有场景都套用同一种风景；地形、植被、水体、空间组织和氛围应根据各场景分别设计。
3. **场景方向示例不等于最终定案。** 圆桌会议室可以有自己的湖畔景观；辩论室将来可以采用完全不同的环境。具体方案尚未确定，Agent 不得自行给每个场景分配海岸、雪山、雪景、花海或其他最终主题。
4. **统一 Minecraft 美术品质，保留不同环境特色和氛围。** 各场景可以共享品质要求，同时在环境主题、地貌、植被、水体、季节、色彩及光影氛围上拥有各自特色；统一品质不能被解释为统一外景模板。
5. **室外应呈现有深度、自然连续的世界。** 室外环境不应只是简单的平面背景；应能读出近景、中景、远景的关系，以及地形、植被、水体和天空之间的自然延续。具体实现方式尚未指定。

### 4.2 当前与未来的应用边界

- **当前只保留圆桌 3D。** 本节记录审美要求，不授权本次修改场景代码或重做美术，也不要求恢复辩论室及其他已退役 3D 场景。
- **差异化约束面向未来设计。** 如用户以后明确授权新增或恢复其他 3D 场景，外景必须分别设计；不能直接复制圆桌湖畔景观作为所有场景的共同模板。
- **最终方案仍由用户决定。** 圆桌湖畔是用户给出的方向示例；圆桌最终外景及其构成、未来辩论室环境和各场景参考元素的组合尚未确定。O01–O04 是品质与空间关系参考，没有“某张图已分配给某场景”的决定。
- **审美确认与视觉验收分离。** 用户认可这些室外要求，不代表认可现有圆桌外景或宣布圆桌正式版完成。室内已确认方向继续按第 3 节保留。

## 5. 跨图片的候选视觉语言（具体形式与实现仍待确认）

第 3 节的四个室内审美方向和第 4 节的五项室外要求已由用户确认；本节对其成因、具体形式、组合与技术实现的解释仍是**工作假设**，不是最终设计方案。自然连续、具有纵深的室外世界及未来场景差异化不得再降为待确认偏好。

1. **室外世界有真实纵深、自然连续，已获用户确认。** R02–R05 与 O01–O04 均可观察到不同距离的物体、遮挡和大气层次。对于圆桌，从窗框/檐下到近岸、水面、树木、远山的具体空间组织仍可探索，但不预先指定元素组合。
2. **光照是空间塑造手段，不是全屏调色滤镜。** R01、R05 强调冷暖光源反差，R02、R03、R06、R07 则强调有方向的日光、遮挡、投影和明暗过渡。不能简单推断用户希望“全部明亮”或“全部暖黄”；季节和时段尚未定。
3. **室内有家具尺度和材质对比。** R06–R08 的木材、布、石材、玻璃、植物呈现不同视觉角色；桌椅、地板、梁架应有结构层次，而不是同材质的单一方盒。
4. **丰富但有主次。** 室内细节与室外植被都较丰富，但画面仍能找到窗景、主座或家具等视觉中心。圆桌场景需优先保证人物、座椅、议事桌可辨认，再考虑装饰密度。
5. **“Minecraft 方块世界”与高级渲染可以并存。** 图片保留体素/方块造型，同时通过材质、形体组合、光线、反射、植被和空间层次提升品质；不等于要把方块改成照片级现实物件。
6. **色彩没有单一已确认配方。** R01、R05 冷暗，R03、R04 户外鲜亮，R06 深木色，R07 自然暖木，R08 浅奶油色。不能据此自选一个全局色板、强行一键暖化，或宣称用户只喜欢低饱和度。
7. **室内观感与室外世界应分别建模。** 参考图既有外观风景也有家居近景；“窗外壮阔”不意味着会议室室内要占满壮阔景物。

## 6. 圆桌样板下一次视觉对照应观察什么

仅列**观察轴**，不是强制的尺寸参数、性能门槛或已获批设计。

| 观察轴 | 同机位真实渲染中应回答的问题 |
|---|---|
| 场景主次 | 八个人物与圆桌是否是视线中心？门窗、吊灯、花草是否争夺注意力？ |
| 空间可读性 | 室内深度、桌椅活动范围、前后景遮挡是否合理？ |
| 窗外世界 | 是否体现第 4 节已确认的自然、精致、丰富层次与空间深度？近景、中景、远景是否连接成自然连续的世界？ |
| 光影 | 光从哪里来，投影与结构是否对应？室内阴影是否压得过黑、暖光是否过黄？ |
| 材质 | 地板、桌椅、梁架是否具有区别；木纹、布料、石、叶、水是否仍保持体素风格？ |
| 细节密度 | 有没有“空盒子感”或反过来的“道具堆砌感”？装饰是否支持圆桌交流的主题？ |
| 远近一致性 | 近景高细节与窗外景观是否像处于同一个可探索的世界？ |
| 运行落地 | 截图是否来自真正的 Three.js 场景，而非生成图/概念拼贴？美术模拟是否依赖未经许可的第三方资源？ |

制作方案时，需先说明参考图的哪一部分被借鉴，以及相应的实际场景几何、材质或光照如何实现。不能以增大 Bloom、全局曝光或统一暖色滤镜取代结构、比例与空间问题。
