# 娱乐组：需要提交的内容（娱乐模式）

仓库：https://github.com/Maxworkinghard/muti-agent，前端在 `roundtable-ui/`。

## 一、人物

每个人物一个 JSON 文件，放在 `roundtable-ui/personas/entertainment/`。数量和内容由你们决定。放好后，删除同一目录下的 `demo-*.json`。

文件格式为 `{ "schemaVersion": "1.0", "persona": { ... } }`，`persona` 需要包含以下字段：

| 字段 | 包含 |
|---|---|
| id | 唯一标识：小写字母开头，只含小写字母、数字和单个短横线，例如 aleng、ent-cold-observer-001 |
| name / displayName | 名字 / 显示名 |
| description | 一句话介绍 |
| version | 版本号 |
| modes | 适用模式 |
| identity | role、profession、fields、responsibilities（1-5 条）、originType |
| knowledge | domains、strong、weak、sourcePreference |
| worldview | tradition、coreValues（1-7 条）、valuePriority、assumptions、judgmentFocus、blindSpots |
| personality | traitOptions（2-8 项，每项含 id、label、behaviors）、defaultTraits（2-4 项） |
| communicationStyle | tone、verbosity、register、sentenceStyle、humor、emotionalExpression、catchphrases（最多 5 条）、avoidPhrases |
| boundaries | uncertainty、outOfScope、factVsOpinion、forbiddenTopics、mustNot（至少 1 条） |
| visual | avatar、color（#RRGGBB）、icon、defaultLabel（不超过 12 字） |

本模式的额外要求：

- `modes` 包含 `"entertainment"`

校验命令：`node persona-protocol/src/cli.mjs validate <文件>`

参考样例：`personas/entertainment/ent-cold-observer-001.persona.json`

## 二、引擎需要包含的部分（具体怎么做由你们决定）

引擎就是在座人物讨论问题、解决问题的整套过程。提交时需要包含以下部分，并附一份简短说明（放在引擎目录下的 `README.md`），写清楚每一部分你们是怎么做的：

1. **讨论流程**：一共几轮（轮次名要和前端一致），每一轮的目标是什么。比如第一轮各自亮出观点，第二轮回应别人的观点。
2. **发言顺序**：每一轮谁先说、谁后说，一个人能不能连续说，要不要插嘴。
3. **每个人能看到什么**：发言前能读到哪些内容，比如前面所有人的发言、只看上一个人的发言，或者只看对方的发言；对话历史保留多长。
4. **人物怎么体现**：人物 JSON 里的身份、知识、思想、性格、说话方式、底线，怎样影响他的发言。
5. **用户插话**：用户发消息或向某个人提问时，由谁回应、什么时候回应，回应完怎样回到原来的流程。
6. **结束与结论**：什么时候结束，最后的共识、分歧、待解决问题、建议是怎么得出来的。
7. **异常处理**：用户点击停止，或者 AI 调用出错、超时，这时候怎么办。

以上内容通过下面的接口接进前端。

## 三、引擎接口

代码放在 `roundtable-ui/src/engines/entertainment/`，由 `index.ts` 默认导出下面这个对象：

```ts
{ mode: 'entertainment', name, owner, create, defaults }
```

其中 `create()` 返回：

```ts
{
  start(config: SessionConfig, emit: (e: EngineEvent) => void): void;
  sendUserMessage(input: { text: string; targetAgentId?: string }): void;
  stop(): void;
}
```

引擎的输入和输出格式如下，完整定义见 `src/types.ts`，这个文件不要修改。

**输入** `SessionConfig`：`{ sessionId, mode, sceneId, theme:{title, brief}, maxRounds, participants[], engineOptions, createdAt }`

讨论页不会自动开始。用户必须先在输入框里详细写下自己对项目的理解，发送后前端才调用 `start()`。这段话放在 `theme.brief` 里传给引擎，讨论要围绕它展开。前端已经把它作为第 0 轮的用户消息显示出来，引擎不需要再回显。

participant 的格式：`{ agentId, seatIndex, color, personalityId, persona, side?, isLead? }`。其中 `persona.protocol` 就是你们提交的人物 JSON。

**输出** 通过 `emit` 发出的事件：

| 事件 | 格式 |
|---|---|
| session | `{type:'session', state:'running'|'finished'|'stopped'}` |
| round | `{type:'round', round, label}` |
| status | `{type:'status', agentId, state:'idle'|'thinking'|'speaking'|'working'|'done', action?}` |
| message | `{type:'message', message:{ id, round, speakerId, text, kind:'speech'|'user'|'reply'|'system'|'task', targetId?, at }}` |
| task | `{type:'task', task:{ id, title, from, to, status:'assigned'|'handoff'|'done' }}` |
| result | `{type:'result', result:{ consensus[], disagreements[], openQuestions[], suggestions[], deliverables?[] }}` |

`speakerId` 填发言人的 agentId，用户发的消息填 `'user'`。用户对某个成员说的话，`targetId` 填该成员的 agentId；回应用户的消息，`targetId` 填 `'user'`。
