# 新增 3D 场景资源

## 接入范围

原有 `roundtable`、`debate`、`office`、`classroom`、`meadow` 的图片、座位与默认显示保持原样。四个新增入口使用 `roundtable-3d`、`debate-3d`、`office-3d`、`debate-meshy` 独立 ID，只有用户主动选择它们时加载 GLB。模式默认值仍指向原来的像素场景。

`debate-meshy`（界面上叫「辩论室 · 精模」）用的是 `scene-debate-meshy.glb`：按原辩论室重做的立体房间，蓝桌红桌、讲台、墙面书架都在。注意它**必须**走 GLB 这条路——一旦给它设上 `pixelStage`，代码搭的那个简化房间会顶掉真模型，画面立刻退回粗糙版。

## 精模的精修

按真实房间结构修正原 AI 模型：保留两侧长桌、椅子、中央讲台及七席布局，清除带有透视变形的墙面、窗框与边缘碎片，重做垂直墙面、矩形窗洞、水平天花板、门框与顶灯。校平两侧桌面的 594 个顶点；修复依墙摆放的书架、长椅与盆栽，支撑落地。保留家具贴图的 UV，清理孤立噪点，移除残留法线及金属／粗糙度贴图，采用最近邻采样和哑光材质。

当前共 21,244 个三角面，GLB 为 2,494,348 字节，约 2.38 MiB；原始精模为 75,625 个三角面、11,859,480 字节。静态家具合并，四面墙和顶部独立分组。`stageCeiling`、`stageWall` 从 glTF 父节点传到子网格；俯视隐藏顶部和镜头这一侧的墙，旋转后自动改变剖切方向。座位射线始终排除顶部。

`Mesh_0` 的 `roomMetrics` 定义地面、顶面、眼高和人物世界高度。相机采用水平视线，人的眼高按桌高比例标定；人物身体按视场角和景深投影缩放，名牌保留固定字号。四个 GLB 房间都启用柔和接触阴影，阴影相机按各自外框取景（`SceneStage3D.tsx` 模型加载处）。

复现时对未经精修的原 GLB 执行（脚本会拒绝重复精修）：

```powershell
blender -b -t 4 --python-exit-code 1 -P scripts/polish-debate-room.py -- --source "原始精模.glb"
```

缩略图取自网页实际 `SceneStage3D` 的室内视角；导出时隐藏人物与操作按钮。原始贴图的调色过程见下节，其中尺寸数据是精修前的数据。

## 精模的贴图：把 AI 绘画改成像素画

这个模型是 AI 生成的，baseColor 是一张 2048² 的**绘画**：约 20 万个不同颜色、相邻像素平滑过渡——和像素画的"大色块 + 硬边"是两个路子，所以直接渲染出来总有一股"AI 建模味"，和旁边几张像素图放一起不搭。法线贴图（4.89MB）还额外糊了一层柔和明暗。

处理办法：**把 baseColor 的每个纹素吸附到原辩论室像素图自己的调色板上**，并按像素画的方式关掉法线/粗糙/金属贴图、改用最近邻采样。着色器的光照保持不动，等于让贴图自己承担"像素"这件事。

- 调色板取自 `frontend/public/scenes/scene-debate.png`，中位切分到 48 色后再按 26 的距离去重，得 16 色
- **必须用原图的调色板，不能用模型自己的**：模型调色板里几乎没有纯蓝（蓝窗只有 7 个偏青的蓝），拿它自己当基准会把蓝窗吸附成墨绿。原图调色板保留了这些色相
- 结果：2048² 的 32 色图，1.39MB（原 jpg 3.72MB），整个 GLB 从 14.56MB 降到 11.31MB

复现（脚本用 `@gltf-transform/core` + `sharp`，不进仓库）：

```js
// 1) 从 scene-debate.png 取调色板 -> pal-src.json（16 色）
// 2) 对 GLB 里名为 Image_0 的贴图逐像素吸附，重编码为调色板 PNG
// 3) 写回 GLB
```

原文件已备份在项目外；重贴图只改贴图，网格、UV、包围盒、座位点全部未动。

## 两种视角

这三个房间是把原来的像素场景按同一套配色、同一批家具做成立体的，所以**默认就走进去看**：相机站在靠观众那一侧、约 1.6 米高，朝房间中心看，和像素图的视点一致，只是能转头、能推拉。觉得屋里看不全整间房时，点画布右上角的「⊞ 俯视」切到正交俯瞰（就是以前那个绕圈旋转的视角），再点「◉ 进屋」切回来。

朝向只有「进屋」那一档接管鼠标：拖动转头、滚轮推拉镜头（只改视场角，不会撞墙）。「俯视」那一档把鼠标交回 OrbitControls。

站位可以在 `SceneStage3D.tsx` 的 `ROOM_VIEW` 调（`eye` 眼高、`back` 往观众侧退多少、`look` 视线落点高度），个别房间里正中间摆着大家具（例如圆桌那张正对镜头的大椅子）时用 `SCENE_VIEW` 单独挪开。人物名牌按胸口高度投影；站在镜头背后的人会被收起（显示为 -100%），不会把名牌甩到画面外。

### 三个房间的 v2 精修（2026-10）

在 v1（贴图吸附：中位切分调色板、逐纹素吸附、删噪点碎片、断开法线/ORM 贴图、最近邻采样；座位点逐席一致；圆桌 14.5→8.0 MB、辩论 15.2→8.5 MB、办公室 17.0→9.5 MB）之上追加两项，脚本 `polish-room-textures.py` + `polish-room-geometry.py`：

- **阴影感知调色板**：像素数最多的 8 个色块各补 0.8 / 0.6 两档同色相暗色。AI 原画的烘焙阴影因此吸到「同色相的暗色调」（经典像素画的两档明暗），而不是描边墨色——办公室柜面等处的深色斑块改成正常的阴影过渡。
- **墙面矫直**：四侧墙各自拟合竖直平面，把墙面顶点按「平面位置 − 墙中位」的低频偏移拉直，窗洞凹进、贴墙家具的厚度差保留。安全护栏：只移动邻面全部在带内的顶点（融合网格里和带外几何共享的顶点不动，否则会把相连的桌面拉裂），平面拟合噪声过大的面直接跳过。实测矫直量 0.2–3 cm。

已知残留：辩论室左侧墙仍可见倾斜——可见倾斜量超过安全矫直的上限（和家具共享的顶点不能动），彻底矫平需要照精模的做法「删壳重建」；房间材质的像素化程度已与像素小人统一。

注意：Blender 5.2 的 `image.pixels` 对 8 位图返回的是 sRGB 原始值（用参考图已知位置的采样验证过），贴图脚本因此直接在 sRGB 空间匹配与写回，不做线性转换——多做一次转换会把调色板整体压暗、暗部色相挤成一团。

## 颜色还原

**结论：模型自带的 base color 贴图本来就是忠实的，问题出在渲染。**

把贴图直接贴到平面上、只和源 PNG 比，对着模型自身的 UV 逐点采样后平均每通道只差 13.5（0–255），源图平均饱和度 0.293、贴图 0.290——之前"贴图比源图淡三成"的判断是错的。真正的损耗来自叠加在上面的 filmic 色调映射和过强的方向光：ACES/Neutral 会把这种手绘像素图的高饱和中间调压掉，于是整个房间发灰发白。

### 定的参数

用一个无光照 pass（`MeshBasicMaterial`，直接输出贴图）当基准，扫光照强度 × 饱和度 × 色调映射，逐像素算与基准的平均绝对差：

| 配置 | roundtable | debate | office | 平均 |
| --- | --- | --- | --- | --- |
| 之前：Neutral + sat 1.42 + 半球光 2.4 + 主光 1.9 | 20.7 | 18.2 | 17.9 | 18.9 |
| 现在：NoToneMapping + sat 1.0 + 半球光 3.0 + 主光 0.4 / 补光 0.1 | 11.6 | 5.8 | 10.0 | **9.1** |

半球光强度 3.0 接近"整个天穹都被照亮"的辐照度，是让漫反射贴图颜色原样透出来的条件；保留一档很弱的主光只为了让人和家具仍有立体感。饱和度校正不再需要（`sat = 1`，`boostSaturation` 保留为按场景调色的开关）。

### 调整方向

参数在 `frontend/src/components/SceneStage3D.tsx` 的 `STAGE_TUNING`：

| 目标 | 改什么 |
| --- | --- |
| 整体更亮 / 更暗 | `hemi`（当前 3.0）——这是主要亮度旋钮 |
| 更艳 / 更淡 | `sat`（当前 1.0；改离 1 才启用 luma 校正） |
| 立体感 / 明暗对比 | `key`、`fill`（当前 0.4 / 0.1） |

改这些不需要重新导出 GLB，也不用再动 Meshy。

`scene-*-preview.png` 已按上面这套参数重渲染，和网页里看到的一致。
