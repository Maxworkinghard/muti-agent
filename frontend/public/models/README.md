## 接入范围

原有 `roundtable`、`debate`、`office`、`classroom`、`meadow` 的图片、座位与默认显示保持原样。三个新增入口使用 `roundtable-3d`、`debate-3d`、`office-3d` 独立 ID，只有用户主动选择它们时加载 GLB。模式默认值仍指向原来的像素场景。

三个 `scene-*.glb` 来自项目外 `场景/3d-models/` 的同名文件，源文件未改动。网页版本保留原始 2048×2048 贴图，每间约 18 万三角面；`scene-*-preview.png` 按 `STAGE_TUNING` 的实际渲染缩略图（见下"颜色还原"）。在 `frontend/` 下重新导出：

```powershell

```

目前沿用每位人物原有的像素形象、表情和发言／思考／工作动画。三个模型各自有独立标定的 `modelSeats`，按真实桌椅位置投影到画面；切回 2D 时使用原来的 `seats`。讨论与任务传递仍可使用。之前生成的通用 Meshy 人物未通过视觉验收，已经从网页加载逻辑和公开资源中撤下，原始生成文件保留在项目外 `场景/meshy/`。

## 颜色还原

**结论：模型自带的 base color 贴图本来就是忠实的，问题出在渲染。**

把贴图直接贴到平面上、只和源 PNG 比，对着模型自身的 UV 逐点采样后平均每通道只差 13.5（0–255），源图平均饱和度 0.293、贴图 0.290——之前"贴图比源图淡三成"的判断是错的。真正的损耗来自叠加在上面的 filmic 色调映射和过强的方向光：ACES/Neutral 会把这种手绘像素图的高饱和中间调压掉，于是整个房间发灰发白。

### 定的参数

用一个无光照 pass（`MeshBasicMaterial`，直接输出贴图）当基准，扫光照强度 × 饱和度 × 色调映射，逐像素算与基准的平均绝对差：

| 配置 | roundtable | debate | office | 平均 |
| --- | --- | --- | --- | --- |
| 之前：Neutral + sat 1.42 + 半球光 2.4 + 主光 1.9 | 20.7 | 18.2 | 17.9 | 18.9 |
| 现在：NoToneMapping + sat 1.0 + 半球光 3.0 + 主光 0.4 / 补光 0.1 | 11.6 | 5.8 | 10.0 | **9.1** |

半球光强度 3.0 接近"整个天穹都被照亮"的辐照度，是让漫反射贴图颜色原样透出来的条件；保留一档很弱的主光只为了让人和家具仍有立体感。饱和度校正不再需要（`sat = 1`，`boostSaturation` 保留为按场景调色的开关）。

### 调整方向

参数在 `frontend/src/components/SceneStage3D.tsx` 的 `STAGE_TUNING`：

| 目标 | 改什么 |
| --- | --- |
| 整体更亮 / 更暗 | `hemi`（当前 3.0）——这是主要亮度旋钮 |
| 更艳 / 更淡 | `sat`（当前 1.0；改离 1 才启用 luma 校正） |
| 立体感 / 明暗对比 | `key`、`fill`（当前 0.4 / 0.1） |

改这些不需要重新导出 GLB，也不用再动 Meshy。

`scene-*-preview.png` 已按上面这套参数重渲染，和网页里看到的一致。
