# 工作引擎（工作 · 创造项目）

像一支真实的团队在一间办公室里干活：负责人开站会派活，大家分头做，需要时走到同事工位当面问；写完第一版交给同事评审，当面回应后改出第二版；交付前负责人对一遍各部分，有冲突就把相关的人叫进会议室对齐、拍板，最后在交换台前宣布交付。

流程跑在 Node 后端，前端用 `createBackendEngine`（`../backend.ts`）发起会话，经 SSE 接收事件。

| 文件 | 内容 |
| --- | --- |
| `index.ts` | 引擎包：`create` 是 `createBackendEngine` |
| `config.ts` | 可调参数：`pace`（节奏倍数，默认 1；0 表示不等，测试用）、`parallel`（最多几个人同时调用模型，默认 4，范围 1～8） |
| `server/work.ts` | 四轮流程、台上调度 `Stage`、每个人此刻在干什么 `Presence`，以及从回答里认出「找谁」「请谁评审」「叫谁开会」 |
| `server/session.ts` | 会话：每位成员一段模型对话、同一个人的请求排队、暂停、停止、用户插话、私聊、记录员总结 |
| `src/data/stageRules.ts` | 前后端共用的台上规矩：走到哪、走多久（按距离算）、一句话在气泡里停多久 |
| `scripts/check-work.mjs` | `npm run test:work`：假模型跑 13 人全流程，按事件时间逐条核对台上规矩，覆盖暂停、停止和失败 |

（`index.ts` 和 `config.ts` 相对此目录，其余路径相对 `frontend/`。）

人物在 `frontend/personas/product/`，共 13 个，见[人物库说明](../../../personas/README.md)。选人页里第一个入座的人默认是负责人，可以改。

## 1. 讨论流程

一共四轮，轮次名和 `src/data/modes.ts` 一致：

1. **立项派活**
   - 全组错开起身，围到中央交换台站成一圈。
   - 人到齐后，负责人讲拆分思路，给每位成员各派一项任务。任务由模型输出 JSON；解析不出时，按各人的专长兜底。
   - 讲完大家回工位，任务文件经交换台飞到各个工位。
2. **分头干活**
   - 所有成员同时开工，最多 `parallel` 个人同时调用模型。
   - 每人先想要不要当面找一位同事对一下，最多找一位。要找的话，走到对方工位旁当面问，对方回答，听完再回来。
   - 然后写第一版，末尾点一位最适合挑毛病的同事来评审。
   - 第一版是交出来的文件：气泡里看要点，记录里按文件样式显示全文。
3. **互相评审**
   - 第一版送给作者点名的那位同事。点的是自己、负责人或已经排满，就换成手上最空的同事。超过 3 位作者时，每人最多安排两份；人数更少时按实际作者数设置上限。仅有一位成员时，由负责人评审。
   - 评审人看完，走过来当面提意见；作者采纳或反驳，改出第二版。
4. **定稿交付**
   - 负责人对一遍各部分。有冲突就叫上 1～3 位相关的人去左上角会议室，一人一句对齐，负责人当场拍板。
   - 各人把改好的部分经交换台交给负责人。
   - 全组再围到交换台，负责人宣布最终交付。

## 2. 发言顺序

- **站会、会议**：一次一个人说，负责人先开口。会议里被叫的人按顺序说，每人接着前面的人往下说，最后由负责人拍板。
- **分头干活、互相评审**：几组同时进行。每组当面谈的两个人轮流说（问 → 答，评审 → 回应）。一个人同一时间只跟一位同事当面谈，别人正在找他时就先等着。
- **不插嘴、不抢话**：用户的话排在下一步之前回应，见第 5 节。

**台上调度**（`work.ts` 里的 `Stage`）：模型照样几个人同时想、同时写，但说出来、起身走动、交文件都要等台上放行，宁可整场拉长也不挤。规矩如下：

- 一个人话没说完不起身，路没走完不开口。
- 当面谈的两个人轮流说：上一句在气泡里停够看完的时间（按字数 2.5～7 秒），才出下一句。回答在问题还挂在气泡里时就开始生成。
- 站会和会议要等人到齐，一次一个人说；散会时等最后一句看完，再错开起身。
- 工作流程同时最多两个发言气泡，多出来的对话先等着。几份第一版之间至少隔 0.9 秒交；用户提问的回应由会话单独处理。
- 走路时间按距离算（0.7～2.6 秒）。前端动画和后端排时间用的是同一份 `stageRules.ts`。
- 暂停时工作流程不上台，暂停的时间不计入台上的时钟；用户提问和私聊仍可回应。

截图所用的 13 人办公室演示约 5 分钟，实际耗时随模型响应、讨论和会议次数变化。

## 3. 每个人能看到什么

每位成员是一段独立的模型对话，整场保留自己的历史。每次轮到他，先收到他上次之后的新公开记录，再收到这一步的指令。

这是开放式办公室：别人当面谈的话、交上来的第一版、派活和送审记录，他都听得到。每条记录都标着谁对谁说、在干什么。

私聊只发给被点的那个人，不进公开记录，别人拿不到。

## 4. 人物怎么体现

每位成员的 system 提示词由三部分组成：

- **人物文件**：身份、知识、思考方式、价值观、选中的性格和说话风格、口头禅、底线；
- **本场规则**：在座成员、谁是负责人，以及工作模式下「真实团队」的说话方式；
- **统一的说话方式**。

性格决定他找谁、问什么、怎么评审、同不同意。底线照常遵守。

## 5. 用户插话

- **对全体说**：排在下一步之前，由负责人回应；回应完接着原来的流程。
- **点成员说**：算私聊，只有他看得到。他私下回应，不占公开发言位。
- **暂停中和结束后**：暂停时也能说话、私聊；讨论结束后还能接着追问。

## 6. 结束与结论

负责人宣布交付后，由单独的记录员把全程整理成五部分：

- 共识；
- 分歧；
- 待验证的问题；
- 建议；
- 交付物：按「名字：产出」列出每个人交了什么。

## 7. 异常处理

- **停止**：中断在途的模型请求，取消走路、气泡这些等待，之后不再发出任何工作事件。
- **调用失败**：
  - 每次调用默认 180 秒超时。可重试的失败先等 3 秒，再试一次。
  - 关键步骤仍然失败，就停下并提示「本次工作未交付」，已发出的记录会保留。关键步骤包括派活、开工准备、当面讨论、第一版、评审、第二版、交付检查、会议和定稿。
  - 连续 3 次失败，或鉴权、余额、模型不存在等不可重试的错误，直接停止。
- **总结失败**：提示「整理结论失败」，不会发出 `result` 结论；已有讨论记录保留，仍可继续追问。
- **页面断开**：前端断开一分钟还没回来，会话自动结束。

## 事件

除了通用的 `session`、`round`、`status`、`message`、`result`，工作引擎还用到以下几项：

- **`move`**：`{type:'move', agentId, to}`。`to` 的取值：
  - `desk`：回工位；
  - `huddle`：去站会；
  - `meeting`：去会议室；
  - 同事的 agentId：走到他工位旁。

  只在标了 `stations` 的二维场景（办公室）里画出走动，其他场景里大家留在座位上。
- **`task`**：任务的状态有三种，前端据此画文件飞行和任务板：
  - `assigned`：派活；
  - `review`：送审；
  - `done`：交付。
- **message 的三个字段**：
  - `targetId`：当面说话的那位同事；
  - `tag`：这句话所在的环节，比如站会、第一版、评审、第二版、对齐、拍板、交付；
  - `doc`：标记这是交出来的文件（第一版）。
