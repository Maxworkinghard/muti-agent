# 活人聊天底盘（导演 + 演员）

娱乐和情感分析共用的底盘（玩法分别在 `../entertainment/kit.ts`、`../emotion/kit.ts`）。辩论另有独立引擎（`../rational/`）。

好的群聊不是一个导演说了算：像一部好电影，导演、演员、剧本缺一不可。这里的“剧本”不是每场事先写好的剧情——那会让每场都一个样，也接不住用户随时插话——而是事先写好的人物小传（人物文件）和模式规则；剧情由人物之间现场碰出来。所以权力分开：

| 谁 | 管什么 | 不管什么 |
| --- | --- | --- |
| 导演（每步一次模型调用） | 看全局：提名这一步可能接话的 1~3 个人和各自的话头，把握节奏、旁人的情绪、说话状态、全场走到哪 | 不写台词；不决定最后谁开口；不替人定看法和打算 |
| 引擎（代码） | 按各人此刻的冲动从候选里抽谁开口；硬规则（点名、用户在等）；记账、限速、执行、流水线 | 不判断内容 |
| 演员（每个角色自己的调用） | 按自己的人设决定怎么说；导演的话头只是建议，不合人设可以不照着来；自己报看法、打算、说完这句的心情 | 看不到别人的人设和账，看不到导演的全盘安排 |

| 文件 | 内容 |
| --- | --- |
| `engine.ts` | `createLiveEngine(kit, chatFn?, debug?)`：导演提名、按冲动抽谁开口、演员说、流水线（说这句时下一句已经在准备）、插嘴截断、小反应、冷场散场、分步（`kit.stages`）；暂停、插话、@点名、私聊、出错重试；总结 |
| `mind.ts` | 每个人的账：情绪按性情放大、随发言回落，说话状态（会过期）、看法、打算、好恶、小反应，给模型和界面看的说法 |
| `types.ts` | `LiveKit`（模式要提供的东西）、`Cue` / `Candidate`（导演的提名）、`Speech`（演员说的话和自己报的心思）、`Temperament`、`MoodDef`、`LiveOptions`、读人物扩展字段的 `personaExt` / `readReactions` |
| `schema.ts` | 导演和演员输出里由底盘解析的字段怎么写（候选、小反应、演员的输出格式），各模式共用这一份说明 |
| `json.ts` | 从模型回答里抠 JSON |

## 谁开口：导演提名，现场抽签

1. 导演输出 `candidates`：这一步可能接话的 1~3 个人，每人带冲谁说、话头、建议的情绪、接哪条、要不要插嘴；排第一的是导演首选。
2. 引擎给每个候选算此刻的**冲动**（不问模型）：话多的人门槛低；上头的人（“热”情绪高）憋不住；最新一句冲他来的、看不惯刚说话的人、刚被打断话没说完的更想接；刚说完的让一让；憋了好久的想说两句。
3. **随性程度**（`spontaneity`，0~1，各模式在 `config.ts` 里设）那么大的概率按冲动加权抽一个，否则用导演首选。0 就是以前那样总听导演的；1 完全看现场。
4. **硬规则优先**：用户 @点名的人一定先接（导演没提名他也一样）；用户说了话，只在冲用户说的候选里抽，抽中的人得接他。随机抽中的开场人物照样落实到第一句。

同一个局面，每次可能是不同的人接、从不同的角度接；但都是导演觉得说得通的人，不会乱入。

## 演员自己拿主意

- 导演给演员的是**建议**（冲谁说、话头、情绪、说话状态）。合人设和此刻的心思就顺着说；不合就按自己会怎么说来，输出里写 `follow: false` 和一句理由。理由会写进导演下一步看到的“刚发生的事”，像演员给导演提意见。
- 演员每说一句，自己报：对这件事的看法（`stance`）、接下来的打算（`plan`）、说完这句的心情变化（`mood`）。这些只由演员自己定，导演只能在“每个人现在的账”里看；旁人的情绪变化仍由导演估计（每步有上限，代码按性情放大、限速）。
- 导演改的**说话状态**过 6 次发言自动回到这个人平时的样子，导演再写一次就续上，免得一次判断长期锁住一个人。

## 小反应走人设

导演只定谁、哪一种反应（笑、惊讶、附和、不服、疑问、心疼、敷衍），说什么由引擎从这个人自己的小反应清单（人物文件的 `x-reactions`）里挑，避开他最近用过的；他清单里没有这一种，说明他不会这么反应，就不出声。人物文件没写小反应时（比如用户导入的人物），用导演写的原话。

## 模式要提供什么（`LiveKit`）

- `moods`：在乎哪几种情绪，每种的档位说法、表情、回落速度，被哪项性情放大。
- `temperament(p)`：这个人的性情。
- `directorMessages(x)`：导演的提示词。底盘给好聊天记录、每个人的账、全场阶段、“现在”四段文字；模式负责阵容、导演规则和输出格式（字段见 `engine.ts` 的 `parseCue()`：`arc`、`arc_note`、`candidates[{speaker,to,gist,emotion,reply_to,interrupt,cut_after}]`、`mood`、`style`、`toward`、`react[{who,kind}]`、`topic`、`end`；以前只提一个人的 `next` 也认）。候选、小反应的说明用 `schema.ts` 里的。
- `actorMessages(x)`：演员的提示词（说一句，或者私下回用户）；输出格式用 `schema.ts` 的 `actorSchema`：`say`、`inner`、`stance`、`plan`、`mood`、`follow`、`why`，私聊时 `private_reply` 等。
- `summaryMessages` / `parseSummary`：散场后的总结。
- `stages`（可选）：分步走的模式给出步骤名，比如情感分析的「回应情绪 → 分清事实与感受 → 下一步行动」。导演的 `arc` 写现在在哪一步，走到后面的步骤时界面开一段新的（只往前走，从有人开口算起）；导演看到的“走到哪了”会写成第几步、这一步说了几次。没走到最后一步不散场：导演提前写 `end` 不算数，冷场时停下来等用户开口（这期间不再叫导演，用户对全体说话或点暂停再继续才接着聊）；发言条数用完照样散场。不给 `stages` 就是娱乐那样的自由聊。

换一个模式，通常换的是导演规则（比如辩论导演要追着回避的问题不放）、在乎哪些情绪、要不要分步、随性程度、要不要额外记账（论点账、想法墙）。暂停、插话、私聊、插嘴、抽签、界面不用再写一遍。

## 界面约定

除了通用事件，还会发：`mind`（某人的账变了，界面换表情、显示内心面板）、`message.kind = 'react'`（小反应）、`message.quote`（接的是前面某一条）、`message_update.cut`（这句被打断）、`round`（换话题；分步的模式还有走到了哪一步）。导演的安排不发给界面；`createLiveEngine` 的第三个参数 `debug` 能拿到每一步导演提名了谁、各人冲动多大、抽中了谁，以及演员有没有照导演说，只给命令行调参用（`npm run sim`）。
