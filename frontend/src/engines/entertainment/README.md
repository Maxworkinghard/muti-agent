# 娱乐引擎（娱乐组）

娱乐模式像宿舍里几个室友随口聊天：说话短、顺序随意、以好笑为主。引擎跑在浏览器里，模型调用走同源的 `/api/llm/chat`（`src/llm/client.ts`），Key 只在 `frontend/.env.local` 里。

| 文件 | 内容 |
| --- | --- |
| `index.ts` | 引擎本体 `createEntertainmentEngine`：排队、挑人、发言、插话、总结、停止和重试 |
| `prompt.ts` | 拼提示词：统一规则、人物协议、公开讨论记录、轮次提示；总结用的提示词 |
| `material.ts` | 事实和安全规则，热梗卡 |
| `config.ts` | 可调参数：`memesEnabled`、`memeCount`（3）、`temperature`（0.8）、`summaryTemperature`（0.3） |

人物在 `frontend/personas/entertainment/`，一共 7 个：老方（反驳型）、小正（反反驳型）、阿实（确实型）、小林（正常人）、阿冷、小戏、阿禾。

## 1. 讨论流程

轮次名和前端 `modes.ts` 一致，默认 3 轮：

- **开场破冰**：每人说说对话题的第一反应。
- **脑洞接龙**：接住前面某条具体发言往下延伸，或者补一个新角度。
- **投票收尾**：说说哪个说法最打动自己，想改口也可以直说。

每轮只给一句方向提示，不规定说法。每轮的发言条数在“人数”到“人数 + 2”之间随机。

## 2. 发言顺序

不按座位轮流，也不是一人一句。每轮先放好若干个空的发言位，轮到哪个位子时再根据当时的情况挑人（`pickNext`）：

- 同一个人不连着说两次。
- 老方刚说完、小正在场时，小正有 75% 的概率紧接着说（`COUNTER_FOLLOW_PROB`），开头只用“我反驳！”或“我反驳你的反驳！”。
- 老方说完新的话之前，小正插嘴的权重降到 0.35 倍，免得他没东西可反驳。
- 两个不同的人来回说过之后，阿实插一句的权重提高到 1.6 倍。
- 老方还没开口时权重提高到 1.5 倍，让他早点出场。
- 本轮说得多的人权重下降，其余情况随机。

## 3. 每个人能看到什么

所有人共享同一份公开讨论记录：用户的第一句话、全部发言和用户插话，每条带编号和说话人。发言前能看到从头到现在的完整记录，娱乐讨论一场很短，所以不截断。人物看不到彼此的设定。

## 4. 人物怎么体现

system 提示词由四部分组成：开场说明、统一运行规则（事实和安全边界，对所有人一样，优先于人物设定）、人物协议 `persona` 原文（去掉展示和版本信息），以及本场用户选中的性格（在默认性格之外更突出）。模式规则要求一两句、几十个字、不加名字前缀和动作描写。人物之间也不频繁喊名字，像真实聊天一样直接接话。热梗卡每场随机抽 3 张，人物根据语境决定用不用。

## 5. 用户插话

用户发的消息立刻显示，并写进公开记录。回应插到队列最前面：点名了某个人就由他回应，没点名就随机一人回应。回应完后接着原来的队列往下走，轮次和剩余发言位不变。

## 6. 结束与总结

最后一轮的发言位走完后，由记录员（温度 0.3）读完整记录，输出 JSON 格式的共识、分歧、待解决问题和建议，每项最多 5 条。解析失败时把原文放进“建议”里。然后发 `result` 和 `session: finished`。

## 7. 异常处理

- **点击停止**：`stop()` 调用 `AbortController.abort()` 中断正在生成的请求，清空队列，发出 `session: stopped`。中断不当成错误显示。
- **调用出错或超时**：失败的那一步放回队首，引擎暂停，发出带“重试”按钮的错误卡片。已经生成一半的发言标上“（发言中断）”。点重试后从这一步接着来，挑中的人不变。
- 气泡在收到第一段文字时才创建，重试不会留下空消息。

## 背景音乐

进入娱乐模式讨论页就开始播放 `public/audio/bgm-happy-adventure.mp3`（CC0，来源见同目录 `CREDITS.md`）。讨论开始后音量压低，离开页面时停止，受界面上的静音开关控制。代码在 `src/sound.tsx` 的 `createBgm` 和 `src/components/DiscussionView.tsx`。
