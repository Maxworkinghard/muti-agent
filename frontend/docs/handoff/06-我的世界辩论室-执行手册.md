## 0. 先看这一页

### 0.1 要做什么

给「辩论」模式新增一个场景：**辩论室 · 我的世界**。

- 场景是《我的世界》里的一间辩论室（第三轮从“礼堂”改过来，见 12.15）；
- 方块、物件、人物模型、粒子、音效、字体和界面贴图，都直接取自用户电脑上的游戏文件；
- 辩论引擎发出的每条信息，都用游戏里的东西在台上表现出来。

### 0.2 用户定下的原则（照做，不要自己改）

1. **直接用游戏里的东西。** 用户原话：「这个游戏里面的各种东西可以直接用，等做出来之后我会拿成品和作者交涉」。
2. **先表达信息，再润色外观。** 用户原话：「用到的东西基本上都是服务于场景以及后端到前端的展示形式，其次才用来润色场景的外观等审美特点」。
   - 做法：每用一样游戏元素，先回答“它表达了哪条信息”；
   - 第 3 节的对照表是这份手册的核心，所有表达信息的元素都是初版必做；
   - 纯装饰的往后排。
3. **像真实的辩论赛，物理上也说得通。** 用户原话：「尽可能符合现实工作/娱乐/辩论场景等现实逻辑」「这个游戏……有着极强的物理交互逻辑」。

4. **画面优先于速度。** 用户原话：「视觉效果为速度让步……拉长时间线去缓冲，但最终都会实现」。动作要排队，不能跳过；为了让台上和文字同步，引擎可以等舞台（8.10）。
5. **物件要丰富。** 用户原话：「你要完全利用游戏里可用物，别单纯的用那些固定的几个大方块」「这个游戏既然支持更细节的素材，那我们就尽可能的利用起来」。

### 2.3 辩论引擎会发出什么（第 3 节的“信息来源”）

**事件**（定义在 `types.ts` 的 `EngineEvent`）：

| 事件 | 内容 |
| --- | --- |
| `session` | running、paused、finished、stopped。界面上还有一个开场前的 `waiting` |
| `round` | 第几轮，以及阶段名（label） |
| `status` | 某人的状态：idle、thinking、speaking、done，附带一句动作说明（action） |
| `message` | 一条消息（`ChatMessage`），字段见下表 |
| `message_update` | 流式更新同一条消息的全文；带 `cut` 表示这句被打断 |
| `mind` | 某人的内心状态（`MindView`），字段见下表 |
| `result` | 结果（`DiscussionResult`），字段见下表 |
| `theme` | 自动生成的辩题 |
| `error` | 出错。带 agentId 表示某个人出错，不带表示整场出错；可能附带 retry（重试） |

**消息 `ChatMessage` 的字段**：

| 字段 | 取值 |
| --- | --- |
| `kind` | speech、user、reply、system、notice、react |
| `targetId` | 说给谁 |
| `private` | 是否私聊 |
| `tag` | 身份和环节，如「正方二辩 · 交锋」「主持人 · 开场」 |

**内心状态 `MindView` 的字段**：

| 字段 | 内容 |
| --- | --- |
| `mood` | 各种情绪的数值 |
| `label`、`emoji` | 一句话心情和对应的表情符号 |
| `face` | 表情配件 |
| `inner` | 心里话 |
| `stance` | 立场 |
| `plan` | 打算 |

**结果 `DiscussionResult` 的字段**：

| 字段 | 内容 |
| --- | --- |
| `consensus`、`disagreements`、`openQuestions`、`suggestions`、`summary` | 共识、分歧、待解决的问题、建议、总结 |
| `verdict` | 判定：`winner`、`proScore`、`conScore`、`reason`、`judge`、`motion`（辩题和双方持方） |

**赛程**（见 `schedule.ts`）：

- **开场**：主持在第 1 轮先开场。
- **第 1 轮「立论陈述」**：双方轮流各说一次。
- **中间各轮「交锋质询」**：每位辩手先回答对方的上一个质询，再向 `target`（对方同位置的辩手）提一个问题。
- **最后一轮「总结陈词」**：反方先说，正方后说，`target` 是对方一辩。
- **轮数和阶段名**：总轮数在 2 到 6 之间；超过 3 轮时，中间几轮叫「交锋质询 1」「交锋质询 2」……
- **结尾**：最后出判定。

**一次发言的事件顺序**：

1. `status: thinking`（组织论点）；
2. 调用模型；
3. 发出说话人（以及被质询人）的 `mind`；
4. `status: speaking`（附带 tag）；
5. 每一句先发一条空的 `message`，再用 `message_update` 逐步出字；
6. `status: idle`。

### 3.7 结果（`result`）

**有判定（`verdict`）时**，台上按顺序做：

1. 主持连敲两下钟。
2. 胜方三人扳下各自的拉杆，三盏灯都亮，身边冒绿色星光。
3. 全体起立，面向镜头连蹲两下（这是游戏里玩家打招呼、致意的方式），然后坐下。
4. 辩题板重画：第一行「正方 82 : 76 反方」，下面是辩题。
5. 三盏阶段灯保持全亮。

界面层同时显示：

- **标题**：「正方胜」或「反方胜」（用队色），或者「平局」（金色）；副标题是比分。
- **右上角成就提示**：「辩论结束 · 结果已写入工作区」。
- **P1**：点讲台，打开游戏的书本界面，分页显示总结、判定理由、共识、分歧等。

声音：两次钟声，再加挑战完成的提示音。

**没有判定时**：只敲钟、起立致意，再出成就提示。

**其他字段**（summary、consensus、disagreements、openQuestions、suggestions）：文字太长，不上台，留在右侧结果卡；P1 的书本界面里分页显示。

**判断胜方**：`winner` 含「正方」算正方胜，含「反方」算反方胜，都不含就是平局。

### 3.9 时间和顺序的规矩

- **变化由人做出来**：灯、钟、站起来，都要有人去做。
- **每个人一条动作队列**：按顺序做，不跳过。不同的人可以同时动。
- **先做完再出字**：
  - 发言的气泡，要等这个人的发言前动作做完才出现；
  - 新一轮的第一个气泡，要等主持敲完钟。
  - 为此引擎会等舞台，最多等 4 秒，暂停期间不计时（8.10）。
  - 超过 4 秒，引擎照常往下走，舞台随后补完动作，不丢。
- **同屏最多两个气泡**：第三个要出现时，最早的那个加快淡出（0.2 秒）。文字不会丢，聊天栏和右侧面板里都有。
- **暂停时一切定格**：所有计时都按“舞台时钟”走，暂停期间舞台时钟不走。
- **舞台不显示时引擎不等**：比如切到 2D，或者页签在后台。

参考时长（可以微调）：

| 动作 | 时长 |
| --- | --- |
| 起身、坐下 | 各 0.3 秒 |
| 走一格 | 约 0.45 秒（每秒 2.2 格） |
| 转头 | 0.3 秒 |
| 扳拉杆 | 0.3 秒 |
| 敲钟（挥手部分） | 0.3 秒 |
| 翻书 | 0.5 秒 |
| 蹲一下 | 0.25 秒 |

由此：

- 新一轮的主持动作合计约 2.1 秒；
- 辩手发言前的动作约 1.05 秒；
- 两者都在 4 秒以内。

### 4.7 搭建规矩（写进 `check-mc-room`）

1. **方块合法**：每个方块状态都在 26.3 的 `blockstates` 里，属性名和取值合法，引用的模型和贴图都找得到。
2. **有依托**：
   - 吊挂的灯笼，上方是铁链、栅栏或实心面；
   - 落地的灯笼、蜡烛、花盆和装在地上的拉杆，下方有实心顶面；地毯下方不是空气；
   - 墙上的拉杆、墙上的旗帜、展示框和画，背后有实心面；
   - 悬挂告示牌上方有方块；
   - 钟按 attachment 的取值有依托；
   - 门的上下两半配对，脚下有地；
   - 梯子背后有实心面。
3. **连接状态自动算**：栅栏、玻璃板、铁链、置物架这类会互相连接的方块，连接状态由搭建函数按邻居自动算，不手写。
4. **人的位置**：
   - 座位、发言站位、主持站位、钟旁站位和走动路线上，人的碰撞箱（0.6×1.8×0.6，坐姿按坐着的高度算）不和任何方块的碰撞形状重叠；
   - 每一步的高差不超过 0.6；
   - 坐姿的腿不穿桌子（椅子和桌子之间空着的发言站位就是为这个）。
5. **两队镜像**：两队区域（x 1–7 和 15–21，z 4–11，所有层）把 x 换成 22−x、蓝换成红之后完全一致。主持区和观众席不要求镜像。
6. **镜头**：
   - 默认机位能看到 7 个人的头和肩，以及辩题板、三盏阶段灯；
   - 从镜头到每个人头部、到辩题板四角、到三盏灯的射线，不被方块挡住（桌面挡住坐着的人的下半身可以）。
7. **光照**：人坐着和站着的位置，方块光和天光取大的那个，不低于 9。

## 5. 人物

### 5.1 皮肤：按人物外观生成（P0）

**做法**：每个人物按 `PersonaVisual`（skin、hair、shirt、accent、hairStyle、extras）生成一张 64×64 的标准玩家皮肤，用宽手臂版。不用 Steve 等默认皮肤：七个人会撞脸，也对不上人物。

**贴图布局**（游戏标准，拿 `entity/player/wide/steve.png` 核对）：

| 部位 | 本体位置，尺寸 | 外层位置 |
| --- | --- | --- |
| 头 | (0, 0)，8×8×8 | 帽子层 (32, 0) |
| 身体 | (16, 16)，8×12×4 | 外套层 (16, 32) |
| 右臂 | (40, 16)，4×12×4 | 右袖 (40, 32) |
| 左臂 | (32, 48) | 左袖 (48, 48) |
| 右腿 | (0, 16)，4×12×4 | 右裤 (0, 32) |
| 左腿 | (16, 48) | 左裤 (0, 48) |

一个盒子（宽 w、高 h、深 d，起点 (u, v)）在贴图上这样展开：

- 顶 (u+d, v)，底 (u+d+w, v)；
- 右侧 (u, v+d)，正面 (u+d, v+d)，左侧 (u+d+w, v+d)，背面 (u+2d+w, v+d)。

**画法**：

- **整体质感**：每块颜色都按好皮肤的画法做明暗：顶部亮 8%，底部暗 10%，侧面暗 6%，再加 ±3% 的像素噪点。噪点用人物 id 做种子，保证每次一样。
- **脸**（8×8）：
  - 第 0–1 行是刘海（看发型）；
  - 第 3 行是眉毛（比发色深）；
  - 第 4 行是眼睛：外侧是白眼仁，内侧是瞳孔；
  - 第 5 行是脸颊，脸红时外侧各一个粉色像素；
  - 第 6 行是嘴，第 7 行是下巴（稍暗）。
- **头发**：画在头顶、后脑、两侧（耳朵在两侧第 4–5 行靠前，用肤色），外层负责立体感。
  - `long`：帽子层后面和两侧往下画，外套层后背第 0–4 行也画上头发；
  - `bun`：后脑帽子层画发髻；
  - `cap`：帽子层画衣服颜色的帽子，前沿一行当帽檐；
  - `hood`：帽子层用衣服颜色把脸框起来；
  - `beanie`：帽子层用 accent 颜色，画一道翻边；
  - `spiky`、`curly`：用帽子层边缘的锯齿和斑点表现；
  - `side`、`middle`：头顶画出分缝。
- **衣服**：
  - shirt 用在身体和上臂；
  - accent 用在领口、扣子、袖口；
  - 裤子按衣服的色相自动取一个深色（藏青、炭灰或卡其），鞋两行，鞋底更深。
- **队徽**：胸前右侧 2×2 像素。正方用蓝 `#3C44AA`，反方用红 `#B02E26`，主持用金 `#FED83D`。比赛里选手都戴队徽，这也表达信息。
- **extras**：
  - `glasses` 画在帽子层的眼睛那一行：镜框绕眼一圈，中间有鼻梁；
  - `scarf` 画在外套层，脖子一圈，用 accent 颜色；
  - 其余配件是表情。
- **表情**：只换前脸那 8×8，不重画整张皮肤。

  | 类别 | 表情帧 |
  | --- | --- |
  | 平常 | 平静；眨眼（眼睛那一行变成一条深肤色线，每 3–5 秒眨一次） |
  | 说话 | 嘴型 3 帧：小口 2×1、圆口 2×2、扁口 4×1，说话时每 140 毫秒换一帧 |
  | 情绪 | 火气（眉毛向中间斜着压低）、压力（帽子层右上角一滴浅蓝的汗）、信心（嘴角上扬）、憋屈（脸红，嘴抿成一条） |
  | 配件 | sleepy（眼睛只剩下半）、happy、grin |

### 5.2 模型和动作（P0）

以下是参考游戏原版的数值，可以按画面微调。坐标以脚底为原点、向上为 +y，单位是像素（1 像素 = 1/16 格）。

**模型**：

| 部位 | 轴心 | 盒子范围 |
| --- | --- | --- |
| 头 | (0, 24) | x −4…4，y 24…32，z −4…4 |
| 身体 | — | x −4…4，y 12…24，z −2…2 |
| 右臂 | (−5, 22) | x −8…−4，y 12…24 |
| 左臂 | (5, 22) | 左右对称 |
| 右腿 | (−1.9, 12) | x −3.9…0.1，y 0…12 |
| 左腿 | (1.9, 12) | 左右对称 |

- 外层比本体放大：帽子层 0.5 像素，外套层、袖子、裤子 0.25 像素；
- 整体缩放 0.9375：人高约 1.87 格，眼睛高 1.62 格。

**姿势**：

| 姿势 | 参考值 | 用在什么时候 |
| --- | --- | --- |
| 坐 | 游戏的骑乘坐姿：两腿 xRot −1.4137、yRot ±π/10、zRot ±0.0785；两臂 xRot −π/5。屁股落在楼梯低的那半格上方 2 像素 | 椅子上 |
| 站起、坐下 | 0.3 秒过渡（游戏里是瞬间，这里避免跳变） | 发言前后 |
| 走 | 每秒 2.2 格；手臂和腿按 cos(行进量 × 0.6662) 前后摆，摆幅跟着速度变；每一步按脚下材质放脚步声 | 上前一步、主持去敲钟 |
| 挥手 | 约 0.3 秒，右臂从前上方挥下，身体随之扭转约 0.2 弧度 | 扳拉杆、敲钟、发言强调 |
| 拿着东西 | 右臂 xRot = 原值 × 0.5 − π/10（游戏拿物品的姿势） | 辩手拿书与笔 |
| 写字 | 低头 xRot 约 0.5，拿东西的那只手小幅上下动 | thinking |
| 蹲 | 身体 xRot 0.5；两臂 xRot 加 0.4；腿后移 4 像素；头下沉约 4 像素 | 结束时致意，蹲两下 |
| 吹号角（P1） | 右臂抬到嘴边（xRot ≈ 头的 xRot − 1.48），持续约 1.5 秒 | 开场 |
| 待机 | 两臂 zRot 随 cos(t × 0.09) 在 ±0.05 弧度内轻摆，xRot 随 sin(t × 0.067) ±0.05；t 以 tick 计，每秒 20 tick | 闲着时 |

**看人**：

- 头约 0.3 秒转向目标；
- 头和身体的夹角超过 50° 时，身体跟着转；
- 目标的优先级：队列里的动作 > 事件要求的方向（比如用户说话时看镜头）> 默认（看说话的人）。

**减少动态效果**：用户系统开了“减少动态效果”时，不摆动、不出粒子，站起和坐下直接切换。

### 5.3 人物身上的信息（P0，标了 P1 的除外）

| 项 | 做法 |
| --- | --- |
| 名字牌 | 头顶上方，游戏的样式：25% 透明度的黑底，无描边。前缀是身份，用队色，如「[正方一辩]」，后面的名字用白字。正方蓝 `#5555FF`、反方红 `#FF5555`、主持金 `#FFAA00`（游戏的队伍颜色）。身份用 `schedule.ts` 里生成 tag 的同一套规则：把 `sideName` 和 `role` 导出来复用，不另写一套 |

### 8.3 游戏字体 `mc-font.mjs`

**目标**：网页能用游戏的点阵字显示英文和中文。HTML 界面层和画布（告示牌、辩题板）共用这一个字体。

**字形来源**：

- 读 jar 里的 `font/include/default.json`。
  - 这里是 bitmap 类型的条目，`textures/font/ascii.png` 等图片，每格 8×8；
  - 字的宽度取这一格里最右边那列不透明像素再加 1，字距再加 1。
- 中文来自资源索引里的 `minecraft/font/unifont.zip`。
  - 解压后读 `.hex` 文件，每行是 `编码:点阵十六进制`；
  - 32 位十六进制是 8×16 的字，64 位是 16×16 的字；
  - 游戏里 Unifont 按一半大小显示，这里也一样。

**收字范围**：

- 全部 ASCII 和常用标点；
- GB2312 一、二级汉字（约 6763 个），以及中文标点；
- 其他字退回系统字体。

**生成**：新增开发依赖 `opentype.js`。

- 每个亮着的像素画一个正方形，同一行相连的像素合并成一个长方形，减少点数；
- 字号单位：一个游戏像素 = 128 单位（Unifont 的像素 = 64 单位），字高 8 个游戏像素；
- 输出 `font/mc.ttf`。体积大一点没关系，只在本机用。

**使用**：CSS 里 `@font-face { font-family: 'MCFont'; src: url('/mc/font/mc.ttf'); }`。字号用 16px（两倍像素），或者 8 的其他倍数。

### 8.4 方块模型读取和网格

**方块状态**：

- **variants**：按属性串匹配，空串 `""` 表示没有属性。值是数组时按 weight 挑，用 `hash(x, y, z)` 做种子，保证每次结果一样。
- **multipart**：`when` 支持单个条件、`OR`、`AND`，属性值可以写成 `a|b`。符合条件的 apply 全部叠上去。
- **旋转**：应用 `x`、`y` 旋转（90° 的倍数）和 `uvlock`。uvlock 的意思是旋转后贴图仍和世界对齐。

**模型**：

- 沿着 `parent` 一直合并上去：`textures` 子模型覆盖父模型，`elements` 子模型有就用子模型的；
- `#变量` 一直解析到具体贴图；
- `builtin/entity` 和没有 `elements` 的模型，交给 7.1 的代码去画；
- `ambientocclusion: false` 的模型不做环境光遮蔽。

**元素**：

- `from` 和 `to` 是 0–16 的像素坐标，可以超出这个范围；
- `rotation`：单轴，角度只会是 ±45、±22.5、0，绕 `origin` 转；`rescale` 时按 1/cos 放大，补回旋转造成的缩小；
- 每个面：
  - `uv` 缺省时按元素位置算；
  - `rotation` 是 0/90/180/270；
  - `cullface`：相邻方块在这个方向上是不透明的整块时，这个面不画；
  - `tintindex`：用 8.4 末尾的固定颜色染色；
  - `shade: false` 的面不乘明暗系数；
  - 元素上的 `light_emission` 当最低亮度。

**合并网格**：整个房间合成几块大网格，分三遍画：

| 遍 | 怎么判断 | 怎么画 |
| --- | --- | --- |
| 不透明 | 贴图里没有透明像素 | 正常画 |
| 镂空 | 有完全透明的像素，比如灯笼、铁链、活板门、树叶、玻璃板 | alpha 测试，阈值 0.1 |
| 半透明 | 有半透明像素，比如染色玻璃 | 按距离从远到近排序，关掉深度写入 |

**动画贴图**：按 `.mcmeta` 的帧时间换帧（1 tick = 50 毫秒），用舞台时钟，暂停时停。有 `interpolate` 的在两帧之间混合。

**贴图过滤**：近处用 Nearest。远处要开 mipmap，按每张贴图自己缩小，靠导入时留的边防止串色。

**染色**：

| 方块 | 颜色 |
| --- | --- |
| 草方块顶面、草丛 | `#91BD59` |
| 橡树、深色橡木、丛林树叶和藤蔓 | `#77AB2F` |
| 白桦叶 | `#80A755` |
| 云杉叶 | `#619961` |
| 水 | `#3F76E4` |

白杨的彩叶、樱花不染色，直接用贴图本身的颜色。

### 8.5 光照（和游戏同一套思路）

**光源亮度**：

| 光源 | 亮度 |
| --- | --- |
| 灯笼、亮着的红石灯、海晶灯 | 15 |
| 火把 | 14 |
| 蜡烛 | 每根 3，点着的 3 根就是 9 |

**传播**：

- 方块光从光源向六个方向扩散，每走一格减 1；不透明的整块方块挡光，其余方块（楼梯、台阶、玻璃板等）按透光处理，第一版可以这样简化。
- 天光：露天是 15，往下不衰减，横向每格减 1，玻璃不挡光。

**平滑光照和环境光遮蔽**：

- 每个面的每个顶点，取这个面外侧相邻的 4 格光照，求平均；
- 环境光遮蔽：两侧都被挡住时最暗；被挡住的格子越多越暗。

**面的明暗**：朝上 1.0，朝下 0.5，南北 0.8，东西 0.6。

**光照表**：

- 一张 16×16 的光照表，横轴是方块光，纵轴是天光；
- 亮度曲线是 f / (4 − 3f)，f = 等级 / 15，再按游戏默认 50% 亮度设置做伽马；
- 方块光偏暖色，天光乘上当前天色的系数。

**着色器**：

- 顶点上存 (方块光, 天光)、明暗系数 × 环境光遮蔽、染色；
- 片元里依次做：采样拼图 → 乘染色 → 查光照表 → 乘明暗 → 加雾。

**更新**：

- 红石灯开关时，只重算以它为中心 15 格内的光，并重建受影响的那一小块网格；
- 天色变化时只改光照表。

**人物和实体**：取所在格子的光照值，用同一张光照表。

### 8.6 场景和天空

- **P0**：
  - 天空是固定的午后蓝；远处按天空色起线性雾，从 32 格开始，到 64 格全雾；
  - 窗外如果还没有室外地形，就是天空。
- **P1**（用户已确认要做，是 P1 里第一个做的）：

  - 每轮开始时平滑过渡 10 秒，暂停时停住；
  - 太阳沿天空弧线移动；
  - 天边按太阳方向加日落的橙粉色；
  - 云层用 `environment/clouds.png` 平铺，高度约 y=192，缓慢移动；
  - 天光系数从 1.0 降到约 0.75；
  - 墙上钟的表盘跟着天色走。

### 8.7 人物

- **皮肤**：每人一张皮肤画布。表情只改前脸那 8×8，换完把贴图标记为需要更新。
- **模型**：按 5.2 的盒子和 UV 生成几何体，外层单独一套稍大的盒子。头、身体、四肢各有轴心节点，方便转动。

- **坐**：坐的位置是椅子格子的中心，高度在楼梯低的那半格上。

### 8.8 动作调度 `director.ts`（纯逻辑）

**输入**：

- 舞台时钟 `now`，不含暂停时间；
- 房间锚点（座位、站位、拉杆、钟、讲台、镜头）；
- 演员表：每人的 id、座位号、身份 pro/con/host；
- 事件，由舞台组件从应用状态的变化里翻译出来：
  - session 变化；
  - round 变化；
  - status 变化；
  - 新消息或消息更新；
  - mind 变化；
  - focus 变化；
  - error 出现或清除；
  - result 出现。

**输出**：

- 每人当前的姿势，以及要看的目标；
- 每盏灯、每个拉杆的状态，钟的摆动；
- 要显示的气泡、聊天行、标题、动作栏文字、成就提示；
- 要播放的声音、要冒的粒子；
- 给引擎的完成信号 `('round', n)` 和 `('speech', agentId)`。

**动作类型**：

```ts
type Action =
  | { kind: 'standUp' } | { kind: 'sitDown' }
  | { kind: 'walk'; to: 'stand' | 'seat' | 'bell' | 'host' }          // 走到锚点
  | { kind: 'face'; target: 'camera' | 'north' | 'bell' | 'lectern' | { agent: string } }
  | { kind: 'lever'; id: string; on: boolean }                        // 改拉杆 → 灯跟着变
  | { kind: 'ringBell' } | { kind: 'turnPage' } | { kind: 'swing' }
  | { kind: 'crouch'; times: number } | { kind: 'horn' }
  | { kind: 'wait'; ms: number }
  | { kind: 'signal'; gate: 'round' | 'speech'; key: string };       // 通知引擎可以往下走
```

**规则**：

- 每人一条队列，按第 3.9 节的时长依次执行。
- 气泡等“说话人做完发言前动作”的信号；新一轮的第一个气泡等主持的 `signal('round')`。
- 交锋中的“一对”：一次交锋发言开始时，记下提问人和被问人这一对；站着、但不在这一对里的人，做完自己的动作后坐下。本轮结束时全部坐下。
- 被问的人起身时，不扳拉杆；他自己发言时才扳。

**写成纯函数，方便测试**：

- `step(state, now, input) → { state, outputs }`；
- 不用 `Date.now()` 和定时器，时间全靠传进来的 `now`。

**`check-mc-stage.mjs` 要测的**（用 Vite 的 `ssrLoadModule` 加载 `director.ts`，参照 `check-work.mjs` 的写法，喂一整场快辩的事件序列，时间按假时钟推进）：

1. 每次发言，气泡都出现在这个人的“起身、走、扳拉杆”之后。
2. 任何时刻，灯亮着当且仅当它的主人在发言，或者结果阶段胜方灯全亮。
3. 每一轮的第一个气泡，都在 `ringBell` 之后。
4. 任何时刻气泡不超过 2 个。
5. 暂停期间，舞台状态不变；继续后从原处接着走。
6. 每个排进队列的动作最终都执行了，没有丢。
7. 交锋时，提问人和被问人都站着、互相面对；下一对开始时，上一对坐回去。
8. 立论和总结里的 `targetId` 不会让被指到的人站起来。
9. 私聊不出气泡，只出灰色斜体的聊天行。
10. 出错时这个人半透明；恢复后不透明，聊天栏有“重新加入”。
11. 有判定时按 3.7 的顺序：敲两下钟 → 胜方灯全亮 → 全体起立、蹲两下 → 坐下。

### 11.2 必要物品写实化

**分工**：

| 保持我的世界方块样子 | 做成写实的（必要物品） |
| --- | --- |
| 建筑：墙、地板、梁、柱、窗、门、屋顶；灯笼和铁链；队旗；书架、盆栽、画；室外；观众长凳；人物（玩家模型） | 辩论桌、辩手椅、评委桌椅、会议话筒、桌牌、水瓶、主持讲台和讲稿、桌铃、辩题屏（含阶段条和比分）、舞台灯、辩手手里的提词卡和笔 |

**做法**：

- **建模**：
  - 用 three.js 按真实尺寸程序化建模：圆角盒、圆柱、沿曲线的管子、旋转体、挤出形状；
  - 不用方块，也不用像素贴图；
  - 文件放在 `src/mc/props/`，每件物品一个文件，导出创建函数和会动的部件（按钮、灯环、讲稿页、桌铃按钮、椅子）。全部是我们自己的代码。
- **材质**：用 `MeshPhysicalMaterial`。木纹、拉丝金属、黑色哑光塑料、布面、亚克力、玻璃（透射）、带水的塑料瓶，各按真实的粗糙度和反光来调。
- **表面贴图**：
  - 木纹、布纹、拉丝金属等，用 CC0（公有领域）材质库的贴图，比如 [Poly Haven](https://polyhaven.com/textures) 和 [ambientCG](https://ambientcg.com/)；
  - 用 1K 分辨率，可以进 GitHub；
  - 下载前同样先问用户（文件名、来源、大小），放在 `public/mc/props/textures/`，附一份 `CREDITS.md` 写明来源；
  - 用户同意之前，先用程序生成的纹理顶上。
- **尺寸**：游戏里 1 格 = 1 米，人高约 1.87 米，物品按真实尺寸做（见物品表）。
- **坐标**：下文的位置用世界坐标，单位是米。格子 (x, y, z) 的中心是 (x+0.5, y, z+0.5)。反方的位置是正方的镜像：x 换成 23 − x。
- **碰撞和依托**：物品不再受方块网格限制，但每件都要有碰撞盒和依托（放在地上、桌上或讲台上）。它们一起加入 4.7 的检查：坐姿不穿桌，站位不被挡，镜头射线不被挡。
- **光照**：光照和阴影跟场景走同一套（11.4）。写实物品另外要一张室内的环境反射贴图（加载时在舞台中央拍一张立方体贴图），金属和玻璃才有真实的反光。

### 11.3 高清材质包（只用在方块的部分）

**用 Faithful 64x**：

- 画风和原版一样，清晰度是原版的 4 倍；
- 最新版是 Release 15，2026-09-15 发布，支持 26.3 和 26.2；
- [许可](https://faithfulpack.net/license)允许在网页项目和公开仓库里转发。要求：
  - 在显眼处署名，附官网链接 https://faithfulpack.net 和许可原文；
  - 不得商用，不得冒充官方；
  - 只用需要的部分。

用户接受方块感，不再试照片级的写实包。

**步骤**：

1. **下载前先问用户**：说明文件名、官方来源（faithfulpack.net，或 CurseForge、Modrinth 上的官方页面）和大小，得到明确同意后才下载。只从官方页面下。
2. **放在哪**：压缩包放进游戏的 `F:\MC\.minecraft\versions\26.3\resourcepacks\`（用户在游戏里也能用），不放进仓库。
3. **导入**：运行 `MC_PACK=<压缩包路径> npm run mc:import`。
   - 只取房间、室外和人物用到的方块贴图（从 `rooms/debate.ts` 收集），用材质包的覆盖原版的；
   - 法线和高光：材质包里有 `_n`（法线）、`_s`（高光）就一起导入；没有就在导入时生成。法线用亮度做 Sobel 求导，强度适中；粗糙度按材质类别查表：木 0.7、石 0.85、羊毛 0.95、金属 0.3、玻璃 0.05；
   - 输出到 `public/mc/hd/`：`atlas.png`、`atlas_n.png`、`atlas_s.png`（三张图位置一一对应），以及实体贴图等；
   - 材质包没覆盖的贴图：用原版贴图按最近邻放大到同样的像素密度，免得一块清楚一块糊。这些贴图列在导入汇总里。
4. **署名**：
   - `public/mc/hd/` 里放许可原文 `LICENSE.txt`，以及 `CREDITS.md`，写明包名、作者、链接、用了哪些贴图；
   - 舞台的加载画面上，以及舞台左下角，常驻一行小字：「材质：Faithful 64x · faithfulpack.net」；
   - README 里也写上。
5. **读取和退路**：舞台读 `public/mc/hd/manifest.json`，有就用高清，没有就用原版，不报错。
6. **进仓库**：Faithful 可以按许可进仓库。以后换别的包，先查许可；不允许转发的，写进 `.gitignore`。

**人物跟上**：

- 皮肤改成 4 倍密度（256×256，布局按 64×64 等比放大），脸 32×32，能画出眼神光、眉形、嘴型和衣褶；
- 表情帧也按 4 倍画；
- 人物仍然是方块人。

### 11.4 光影渲染

做法参照游戏光影包，全部用 three.js 0.186 自带的模块实现。

| 效果 | 做法 | 用在哪些画质档 |
| --- | --- | --- |
| 方块的材质 | 方块改用带法线和粗糙度的材质（PBR）：最终颜色 = 底色 ×（间接光 + 直接光）+ 自发光。间接光用现有的游戏光照网格（方块光、天光、环境光遮蔽）；直接光来自下面的太阳和各种灯 | 高、中、低 |
| 写实物品的材质 | 见 11.2；用同一组灯光和阴影，加上加载时拍的环境反射贴图。间接光按物品所在位置，从游戏光照网格里取样 | 高、中、低（低档不要反射） |
| 太阳和阴影 | 方向光按天色（8.6）摆位置：下午太阳在西边，透过西侧高窗在舞台地板和东墙上投出窗格形状的光斑。阴影贴图 4096（中档 2048），边缘柔和（PCF）。人物、写实物品、方块都投影，也都受影 | 高、中 |
| 灯笼和蜡烛 | 每盏都是暖色点光源（约 2700K），按距离衰减。离镜头最近的 8 盏实时计算，其余只靠光照网格。灯笼火焰、蜡烛火苗、话筒灯环、辩题屏都是自发光 | 高、中、低 |
| 舞台灯 | 亮着的舞台灯是一盏带阴影的聚光灯，照向它对准的位置，暖白色，边缘柔和 | 高、中 |
| 环境光遮蔽 | 顶点上的环境光遮蔽加强到游戏原版的力度（墙角明显变暗），再叠一层屏幕空间环境光遮蔽（`GTAOPass`） | 高；中档只有顶点上的 |
| 光柱和浮尘 | 用太阳和舞台灯的阴影贴图在屏幕上做体积光（每像素 16–32 步），能看到窗口斜射的光柱和舞台灯的光束；光里飘少量浮尘粒子 | 高；中档改用画好的假光柱面片 |
| 泛光 | 自发光的部分加柔和泛光（`UnrealBloomPass`，阈值约 0.9） | 高、中 |
| 调色 | `AgXToneMapping` 加一张暖色的 3D 调色表（`LUTPass`），曝光随天色调整；室内偏暖，窗外偏冷 | 全部 |
| 抗锯齿 | `SMAAPass`，或者 4 倍多重采样；像素比最高 2 | 全部 |
| 景深 | 全景里加轻微景深，焦点跟着发言人；人物视角和评委席关掉 | 高 |
| 天空 | 物理天空（three 的 `Sky`），太阳位置跟着天色；云用 `environment/clouds.png`；室外加随高度变化的雾 | 全部 |
| 室外植物 | 树叶和草在顶点里随风轻摆 | 高、中 |

**画质档**：

- 舞台右上角的视角按钮旁边，加一个「画质：高 / 中 / 低」；
- 加载后先测 3 秒帧率自动选档：高档低于 45 帧就降一档；
- 用户可以手动改，选择记在本机。

**性能**：这台电脑在 1544×868 的窗口下，高档不低于 50 帧，中档不低于 60 帧。

### 12.6 人物：动作和神态（写实，P0）

在第 11.5 节的基础上补齐“神态”，按场合做：

| 场合 | 动作 | 神态 |
| --- | --- | --- |
| 发言 | 站起（先前倾再起身，椅子被腿推开、减速停下），扳拉杆开麦（手伸到拉杆上，拉杆和手一起转），一手拿书，另一只手跟着句子打手势 | 嘴型跟着字出现的节奏开合，停顿时合上；看着评委或被质询的人；强调时眉毛上扬、轻点头 |
| 交锋（质询） | 身体转向对方，手指向被问的人 | 提问方挑眉、逼视；被问方先愣一下（眉毛上挑），再皱眉思考或反驳 |
| 被打断 | 话停住，手势收回 | 惊讶（眼睛睁大）后不服或尴尬，按情绪选 |
| 倾听 | 想听的人头跟着说话的人转（不是所有人，见下面的「动作要丰富、自然」）；偶尔换坐姿 | 赞同时点头、不赞同时轻摇头或皱眉（按立场和情绪）；队友发言时侧身看队友，带一点微笑 |
| 思考 | 低头在书上写，偶尔抬头想 | 眼睛看向斜上方、抿嘴 |
| 情绪 | 火气 ≥6 抱臂；压力 ≥6 前倾、手扶桌沿；信心 ≥7 后靠；憋屈 ≥6 低头塌肩 | 脸上同时变：火气皱眉瞪眼、压力眉头紧、信心微笑、憋屈嘴角下垂；情绪变化后 1 秒内能看出来 |
| 空闲（没人说话） | 小幅度的活动：呼吸起伏、换坐姿、翻书、和身边队友侧头说两句（不出声） | 偶尔眨眼、看看四周；同一时刻每个人的动作和节奏都不一样 |
| 主持 | 开场挥手；换轮按讲台按钮、拍铃；翻讲稿 | 宣布时看镜头、带笑；公布结果前停顿一下再说 |
| 结果 | 胜方站起来欢呼（举手、跳一下）、队友之间击掌；负方鼓掌致意后坐下 | 胜方大笑，负方先失落再释然 |

动作的物理要求：手碰到东西的那一刻物件才开始动；物件按自己的手感运动（拉杆一下扳到位、按钮按下回弹、铃锤回弹、书页翻过去）；人和物不穿模、不悬空；所有过渡缓入缓出，头比身体先动，手比身体晚到。

**看哪里（注视规则）**：每个人看的地方要符合现场逻辑，**不能为了全景里看得到脸，让所有人都朝镜头看**。

- 评委席就在全景镜头旁边，朝评委席看，在画面上就是盯着用户。
- 脸的问题靠两队八字摆放（朝观众张开 25°）解决：大家看对方、看主持时，全景里也能看到侧脸和大半张脸。

| 情况 | 谁看哪里 |
| --- | --- |
| 主持在说 | 多数辩手**陆续**看向主持，有人先把手上的事做完再抬头；主持看评委和观众，偶尔扫两队 |
| 辩手在说（立论、总结） | **不是一开口全体就转头**：被点名、被反驳的人和发言人的队友先看过去；其他人陆续看，有人在记笔记、有人和队友交换意见，过一会儿才抬头；看一阵又会移开（看笔记、看队友），再看回来 |
| 交锋 | 提问的人和被问的人互相看；其他人在两人之间来回看 |
| 没人说话（等待开场、换人的间隙） | 各看各的：看主持（主持在场时最常看这里）、看自己的书、和队友对视或侧头说话、扫一眼对方。每 2～6 秒换一次，每个人的节奏错开，不会同时转头。朝评委席看只是偶尔一瞥，同一时刻最多一个人 |
| 思考 | 低头看书、写字，偶尔抬头想 |
| 结束时鞠躬 | 全体面向评委和观众。这是唯一一次所有人同时朝镜头这边 |

**动作要丰富、自然（用户 2026-10-05 要求）**：用户原话：「人物动作也丰富一点，不要一到某个人发言就全体目光看向那个人，动作都自然一点」。

自然的规则：

- **不齐刷刷**：
  - 同一个事件（有人开口、桌铃响、有人站起来）引起的反应，每个人有自己的延迟（约 0.2～3 秒）；
  - 有人先把手上的事做完，有人根本不转头；
  - 除了结束鞠躬，0.5 秒之内最多两个人开始同一个动作；鞠躬也错开 0.1～0.3 秒。
- **注意力会漂**：每个人在几个目标之间按各自的节奏换着看：发言人、自己的书、队友、对方、主持、辩题板。
  - 每段注视约 1.5～6 秒，长短随机；
  - 和自己越相关看得越久：被质询、被点名、被反驳的人一直盯着发言人；同队的人发言时队友看得多。
- **先眼后头再身体**：眼珠先转（4 倍皮肤有瞳孔，可以移动），头再跟过去，角度大于约 60° 时上身才转；转到位时有一点点回弹。转视线的时候常伴一次眨眼。
- **因人而异**：动作的多少和幅度跟性格走（人物的「性格」设定），也跟情绪走（12.6 的情绪表）：
  - 热血的手势多、幅度大；
  - 冷静较真的多记笔记、动作少；
  - 毒舌的爱往后靠、撇嘴笑。
- **不重复**：同一个人 20 秒内不重复同一个小动作；全场同一时刻的动作种类尽量不同。
- **信息动作照常**：起身发言、扳拉杆开麦、交锋时指向对方、桌铃、翻讲稿这些表达信息的动作照常排队完成，自然层的小动作不能盖住它们。全景里谁在发言，仍要靠站着、开麦灯、手势一眼看出来。

动作库（每个人随时从里面挑，按上面的规则排开）：

| 场合 | 可选的动作 |
| --- | --- |
| 坐着听 | 记笔记、翻书、转笔或用笔点桌面、托腮、手指敲桌、往后靠、往前趴在桌上、抱臂、摸后脑勺、揉眼睛、伸伸腰、换一边坐 |
| 和队友 | 侧头小声说话（不出声）、指着书上的一处给队友看、点头附和、碰一下胳膊、递书 |
| 对发言的反应 | 点头、摇头、皱眉、挑眉、撇嘴笑、和队友对视一眼、低头赶紧记下来、举手示意（想插话时） |
| 发言时 | 掰着手指数论点、摊手、往前送手、手按胸口、指向辩题板、指向对方（交锋）、身体重心左右换、说到要点时往前一步 |
| 主持 | 低头看讲稿、看一眼辩题板、朝发言人点头示意开始、伸手请下一位、宣布时张开双手 |
| 等待开场 | 整理书和笔、和队友聊天、四处看看、伸懒腰、看主持、轻轻晃腿 |

检查：

- 有人开始发言后的第 1 秒内，转头看他的最多两个人；
- 任意 20 秒的全景录屏里，台上至少出现 8 种不同的小动作，没有两个人同步做同一个动作；
- 交锋时提问和被问的两人互相看（`test:mc-stage` 已有这条断言）；
- 截图证据要连拍或录屏，单张截图证明不了“自然”。

### 12.11 观众席坐人（已不适用）

场景改成辩论室后没有观众席（12.15），本节只留作记录。当时用户问「观众席坐人的目的是什么」，分析如下：

- **能带来什么**：
  - 现场感：辩论赛有观众才像“现场”，空礼堂是“冷清”的来源之一；
  - 反馈：观众能在开场、出结果这些明确的时刻鼓掌、交头接耳，给台上的事一点回应；
  - 画面层次：前景有观众的后脑勺，像电视转播。
- **代价和限制**：
  - 不表达任何后端信息：引擎没有观众投票、支持率这类数据，观众的反应只能按规则编，属于纯装饰（原则 2：先表达信息）；
  - 全景里看不到：现在的全景机位在观众区中间的过道上（`[11.5,4.3,17]`），三排观众座在 z=17、19、21，都在镜头两侧和身后。只有切到辩手第一人称、朝观众席看时才看得到。要在全景里看到，就得把机位往后拉、人物变小，或者改观众席布局；
  - 多一批人物模型和动作，要占性能和工作量。
- **建议**：先不坐人。“活泼”优先靠全景里看得到的东西：台上的人（12.6 的神态和小动作、结果时的庆祝）、小动物（12.9）和轻快的音乐（12.10）。以后想要现场感，可以在第一排放少量观众，只在开场和出结果时鼓掌、欢呼。

### 12.13 自由视角：WASD 走动，第三人称（用户已确认，排在 12.12 之后做）

用户原话：「可以通过wsad去自由调整视角，就像游戏第三人称那种」。

**2026-10-06 操作补充**：用户随后要求「就想 cs2 那种，观战 demo 的时候」。本次「自由视角」入口改为直接控制飞行镜头；下文原来的 Steve、重力、碰撞、F5 切人称等行走规则保留在「人物视角 → 评委行走」。

- 点「自由视角」立即获得画面焦点：W/S 沿镜头朝向前后飞行，A/D 左右平移，空格/Ctrl 升降，Shift 加速，滚轮调速；Q/E 也可降/升。
- 普通拖动转向；浏览器允许锁定鼠标时支持直接移动鼠标转向。锁定不可用时仍能拖动和使用键盘。
- 飞行不受人物重力限制；依照后续 12.16，镜头限制在室内，避开墙面、地板、天花板和家具实体。暂停辩论时镜头仍可移动。Esc 或「回到默认」返回室内默认机位。
- 点输入框、点击画面外、窗口失焦或切换到 2D 时，立即释放移动按键；再次点画面恢复控制。操作提示持续显示，失去焦点时提示「点击画面继续控制」。
- 证据：`.verify/mc-debate/r11-controls.json`（演示及正式入口实操）、`r11-*-flight.jpg`、`frontend/scripts/check-mc-spectator.mjs`。

**是什么**：

- 视角按钮里加一个「自由视角」，和全景、评委席、人物视角并列；
- 进去后，“你”（评委席上的那个人）站起来，用户操控他在礼堂里走动；
- 镜头像游戏按 F5 的第三人称那样跟在他身后；辩论照常进行，名字牌和气泡照常显示。

**操作**（和游戏一致）：

| 按键 | 作用 |
| --- | --- |
| W / S | 往镜头朝向的前方、后方走 |
| A / D | 往左、往右平移 |
| 空格 | 跳 |
| Ctrl / Shift | 跑 / 潜行（慢走） |
| 鼠标拖动（或点一下画面锁定鼠标，像游戏那样直接移动鼠标） | 转镜头，镜头绕着人物转 |
| 滚轮 | 镜头拉近拉远（约 2～8 米） |
| F5 | 切换第三人称（身后）、第三人称（正面）、第一人称 |
| Esc | 先松开锁定的鼠标；再按一次，或点「回到默认」，回到全景，人物走回评委席坐下 |

**人物和物理**：

- “你”用游戏默认的 Steve 皮肤（`entity/player/wide/steve.png`，已在导入列表里），名字牌是「[评委]你」；
- 走路照游戏的手感：
  - 走路约每秒 4.3 米，跑约每秒 5.6 米；
  - 有重力，有走路的上下起伏和手臂摆动；
  - 能迈上台阶和矮台子（游戏里能直接迈上 0.6 米以内的高度）；
- 碰撞：
  - 不穿墙、不穿桌椅讲台、不穿过别的人物；
  - 被挡住时沿着障碍物滑开，不卡死；
  - 出不了辩论室；
- 镜头碰撞像游戏：身后有墙时镜头自动拉近，不穿到墙里。

**界面和输入**：

- 进入自由视角后画面底部显示一行小提示：「WASD 走动 · 拖动鼠标看四周 · 滚轮远近 · F5 切人称 · Esc 退出」，几秒后变淡；
- 只有点过舞台画面、焦点在舞台上时按键才起作用：在右侧对话框打字时，WASD 不能让人物走动；
- 名字牌避让（12.8 说的往本队外侧挪、避开辩题板和人脸）只在全景里做；自由视角里名字牌就在头顶；
- 触屏设备没有键盘：显示「自由视角需要键盘」，按钮可以按但不进入（以后再做屏幕上的方向键）。

**检查**（录屏为证）：

- 走一圈：从评委席出发，绕两队和讲台一圈再走回来；全程不穿模、不卡住，镜头不进墙；
- 每个按键逐个试，F5 三种人称都切到；
- 在对话框里打一段含 w、a、s、d 的字，人物不动；
- 自由视角里有人发言时，名字牌和气泡位置正确；
- 退出后回到全景，“你”回到评委席坐下，其他视角都照常；
- 走动时帧率不低于 11.4 的要求。

### 12.14 方块材质（待用户选，先做对比）

用户看了现在的样子说「材质有点一般」。

现在方块用的是 Faithful 64x（11.3）。它是原版画风的高清重绘，当初为解决「方块感太严重」而选，和第三轮的 2D 像素风方向不完全一致：墙面有细噪点，石砖发灰，整体偏写实、偏素。

**三个候选**：

| 方案 | 是什么 | 好处 | 代价 |
| --- | --- | --- | --- |
| A 原版 16×16 | 游戏自带的贴图，按最近邻放大 | 像素颗粒粗，和 2D 像素风接近；不用新东西，删掉或停用 `public/mc/hd/` 就能看 | 原版配色偏暗偏灰，不一定够亮 |
| B Faithful 64x | 现在用的 | 清楚，已经做好 | 偏写实、偏素，用户觉得一般 |
| C 按 2D 场景自绘（**建议**） | 只给礼堂用到的约 20 种方块画一套贴图，配色和画法照 2D 像素场景来 | 最贴参照图（`public/scenes/scene-debate.png`），亮、干净、可爱；是我们自己的作品，没有许可问题 | 要画 |

**C 的做法**：

- 范围：用 `rooms/debate.ts` 收集到的方块贴图（导入汇总里列着，约 20 来种）；人物、灯笼、旗帜、粒子、物品贴图不动；
- 每格 16 或 32 像素，2D 场景的配色：青绿地面、奶油墙、暖木、石板灰墙裙、金色点缀；边缘有一像素的深色描边或明暗边，块与块的边界清楚，没有噪点；
- 表达信息的方块，比如红石灯、拉杆、按钮，亮灭状态必须一眼看出来；
- 放在 `public/mc/style/`，像 `hd/` 一样带 `manifest.json`；舞台按 style、hd、原版的顺序找，缺了就往下退，不报错。导入脚本加一个开关选用哪套。

**对比和拍板**：

- 每个方案拍同一组图：全景（等待开场）、一张两队近景、一张辩题板和讲台近景；
- 三组图并排，加上 2D 参照图，交给用户选；
- 选定之前不删任何一套；
- 选第三方的其他材质包时，先查许可（能不能放进公开仓库），下载前问用户，说明文件名、来源和大小。

### 12.15 场景改成辩论室（用户已确认）

用户原话：「辩论场景就用辩论室」。

后续变更：本节的 14×12 米紧凑尺寸、屋外高处俯拍机位已被 12.16 的用户新要求替代；两队、讲台、书架、窗户、队色和辩题板的场景内容继续沿用。

- 全景从屋子前方偏高处往下看，俯角约 35°～45°，接近 2D 参照图的视角：看得到地垫的图案、两队、讲台和后墙的辩题板；

**不变的**：

### 12.17 灯具主照明（2026-10-06，用户明确要求）

用户原话：「我想要用灯来发光，光照作为辅助光源」。结合此前「材质曝光太强了，太白了」「窗户外的光线太耀眼了」的反馈，房间由实际灯具照亮，阳光、天光和环境光负责辅助填暗部。

**要求与检查**：

- 壁灯和吊灯的光源与灯体位置一致，暖光能照到人物、桌面和地板；灯具须有墙面、吊杆或天花板依托。
- 屋顶参与光照传播，不能因为光照计算漏掉屋顶，把整个室内算成露天满亮天光。
- 压低直射太阳和半球环境光，保留窗外天空与下午到傍晚的变化；窗口不能出现大块刺眼白光，傍晚不能靠大幅提高曝光刷白全屋。
- 保持正常曝光、纹理和队色可辨，辩题板和人脸清楚；12.5 的暗像素不超过 10% 的标准仍适用。
- 同机位留白天前后截图，检查傍晚、人物近景和高/中/低画质；记录实际灯位、光照值与亮度分析。

**本轮方案（实现取舍）**：两队及后方过道上方放六盏带吊杆的灯笼，主持两侧补两盏落地灯柱，支架低于辩题板下沿；这八盏提供实时暖白点光，其余壁灯按方块光传播提供间接光。桌灯底座贴着桌面。实际强度和光色按运行画面调节，整体观感由用户评判。
