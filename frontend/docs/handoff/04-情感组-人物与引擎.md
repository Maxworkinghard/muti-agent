# 情感组：需要提交的内容（情感分析模式）

仓库：https://github.com/Maxworkinghard/muti-agent，前端在 `frontend/`。

## 一、人物

每个人物一个 JSON 文件，放在 `frontend/personas/emotion/`，数量和内容由你们决定。前端启动时自动读取，不用改代码；文件按路径排序，文件名前面加数字可以决定先后。

文件格式为人格资料包协议 v1.0：`{ "schemaVersion": "1.0", "persona": { ... } }`，`persona` 需要包含以下字段：

| 字段 | 包含 |
|---|---|
| id | 唯一标识：小写字母开头，只含小写字母、数字和单个短横线，例如 aleng、ent-cold-observer-001 |
| name / displayName | 名字 / 显示名 |
| description | 一句话介绍 |
| version | 版本号 |
| modes | 适用模式 |
| identity | role、profession、fields、responsibilities（1-5 条）、originType |
| knowledge | domains、strong、weak、sourcePreference |
| worldview | tradition、coreValues（1-7 条）、valuePriority、assumptions、judgmentFocus、blindSpots |
| personality | traitOptions（2-8 项，每项含 id、label、behaviors）、defaultTraits（2-4 项） |
| communicationStyle | tone、verbosity、register、sentenceStyle、humor、emotionalExpression、catchphrases（最多 5 条）、avoidPhrases |
| boundaries | uncertainty、outOfScope、factVsOpinion、forbiddenTopics、mustNot（至少 1 条） |
| visual | avatar、color（#RRGGBB）、icon、defaultLabel（不超过 12 字） |

本模式的额外要求：

- `modes` 包含 `"emotion"`

校验命令（在仓库根目录运行）：`node persona-protocol/src/cli.mjs <文件>`

参考样例：`persona-protocol/examples/aleng.persona.json`。也可以用前端简化格式，两种格式的区别见 `frontend/personas/README.md`。

现有的七个回应风格人物（`frontend/personas/emotion/`）用的是前端简化格式，可以照着改，也可以换成协议格式。

`frontend/personas/common/` 里的通用人物现在也出现在本模式；你们的人物到位后，可以把本模式从它们文件里的 `modes` 去掉。

## 二、引擎需要包含的部分（具体怎么做由你们决定）

引擎就是在座人物讨论问题、解决问题的整套过程。提交时需要包含以下部分，并附一份简短说明（放在引擎目录下的 `README.md`），写清楚每一部分你们是怎么做的：

1. **讨论流程**：一共几轮（轮次名要和前端一致），每一轮的目标是什么。比如第一轮各自亮出观点，第二轮回应别人的观点。
2. **发言顺序**：每一轮谁先说、谁后说，一个人能不能连续说，要不要插嘴。
3. **每个人能看到什么**：发言前能读到哪些内容，比如前面所有人的发言、只看上一个人的发言，或者只看对方的发言；对话历史保留多长。
4. **人物怎么体现**：人物文件里的身份、知识、思想、性格、说话方式、底线，怎样影响他的发言。
5. **用户插话**：用户发消息或向某个人提问时，由谁回应、什么时候回应，回应完怎样回到原来的流程。点成员的私聊只让被点的人看到——不进公开记录、不占公开发言位，别按公开插话处理（其他模式都是这么做的）。
6. **结束与结论**：什么时候结束，最后的共识、分歧、待解决问题、建议是怎么得出来的。
7. **异常处理**：用户点击停止，或者 AI 调用出错、超时，这时候怎么办。

以上内容通过下面的接口接进前端。

## 三、引擎接口

代码放在 `frontend/src/engines/emotion/`：`index.ts` 导出下面这个对象，`registry.ts` 按模式取用；`config.ts` 放可调参数的默认值，开讨论时会复制到 `config.engineOptions`。

```ts
{ mode: 'emotion', name, owner, create, defaults }
```

现在 `create` 是 `createLiveEngine(createEmotionKit())`：和娱乐模式共用导演 + 演员底盘（`src/engines/live/`），情感的导演规则、情绪、三步和总结在 `src/engines/emotion/`，上面七项分别怎么做的写在该目录的 `README.md`，人物的性情写在人物文件的 `x-temperament` 里。要调整时优先改 `emotion/prompt.ts` 的导演规则和人物的 `x-temperament`；要换成完全不同的流程，把 `create` 换成自己的实现即可；在浏览器里调用模型用 `src/llm/client.ts`（写法见 `src/engines/README.md` 的「调用 AI」），不要把 Key 写进前端代码。

`create()` 返回：

```ts
{
  start(config: SessionConfig, emit: (e: EngineEvent) => void): void;
  sendUserMessage(input: { text: string; targetAgentId?: string }): void;
  stop(): void;
}
```

引擎的输入和输出格式如下，完整定义见 `src/types.ts`，这个文件不要修改。

**输入** `SessionConfig`：`{ sessionId, mode, sceneId, theme:{title, brief}, maxRounds, participants[], engineOptions, createdAt }`

讨论页不会自动开始。用户先在输入框里写下想讨论的内容（也可以只说一句“开始吧”），发送后前端才调用 `start()`。这段话放在 `theme.brief` 里传给引擎，讨论要围绕它展开：没填主题时它就是要讨论的问题，填了主题时它是补充说明。前端已经把它作为第 0 轮的用户消息显示出来，引擎不需要再回显。

participant 的格式：`{ agentId, seatIndex, color, personalityId, persona, side?, isLead? }`。`personalityId` 是用户在选人物页选的性格；用协议格式提交的人物，`persona.protocol` 就是文件里 `persona` 的原文。
**输出** 通过 `emit` 发出的事件：

| 事件 | 格式 |
|---|---|
| session | `{type:'session', state:'running'\|'finished'\|'stopped'}` |
| round | `{type:'round', round, label}` |
| status | `{type:'status', agentId, state:'idle'\|'thinking'\|'speaking'\|'working'\|'done', action}` |
| message | `{type:'message', message:{ id, round, speakerId, text, kind:'speech'\|'user'\|'reply'\|'system'\|'task'\|'notice', targetId?, at, meta? }}` |
| message_update | `{type:'message_update', id, text}`：流式发言时，按同一个 id 更新全文 |
| task | `{type:'task', task:{ id, title, from, to, status:'assigned'\|'handoff'\|'done' }}` |
| result | `{type:'result', result:{ consensus[], disagreements[], openQuestions[], suggestions[], deliverables?[], summary? }}` |
| theme | `{type:'theme', title}`：没填主题时，按用户的第一句话起的主题 |
| error | `{type:'error', id, agentId?, message, retry?}`：前端显示错误卡片，给了 retry 时显示“重试”按钮 |

`speakerId` 填发言人的 agentId，用户发的消息填 `'user'`，引擎的提示填 `'system'`（`kind:'notice'`）。用户对某个成员说的话，`targetId` 填该成员的 agentId；回应用户的消息，`targetId` 填 `'user'`。
