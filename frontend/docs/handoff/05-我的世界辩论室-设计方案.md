## 0. 一页看懂

### 画面

这是《我的世界》里的一座学院礼堂：

- **建筑**：奶油色砂岩墙，云杉原木柱，深色橡木横梁；舞台比观众席高一格。
- **辩手**：正方三人坐在西侧（蓝地毯、蓝旗），反方三人坐在东侧（红地毯、红旗），隔着舞台面对面。
- **主持**：站在北边正中的讲台后。身后墙上有一块由 7×2 张地图拼成的辩题板，板下三盏红石灯表示辩论进行到哪个阶段。
- **陈设**：横梁上用铁链吊着灯笼，角落里有书架、盆栽和画。
- **窗外**：草原和树。天色随辩论推进，从午后慢慢变成黄昏。

### 人怎么动

画面上的每个变化，在游戏里都要有说得通的原因：

- **新一轮开始**：主持转身扳下墙上的拉杆，这一阶段的红石灯亮起；然后走到钟旁敲一下，宣布新一轮。
- **辩手发言**：轮到谁，谁就起身向前一步，扳下桌上的拉杆，桌前的红石灯随之亮起（相当于开麦）。然后站着发言，说完扳回拉杆、坐回去。
- **质询**：提问的人和被问的人都站起来，隔着舞台面对面。
- **用户插话**：台上所有人转头看镜头。镜头就是坐在评委席上的你。
- **情绪**：用游戏里的粒子表现。火气冒怒气云，信心闪绿色星光，压力滴水珠，憋屈冒灰烟。

### 素材

方块模型、贴图、人物模型、粒子、音效和字体，都直接取自你电脑上的游戏文件（`F:\MC\.minecraft`，26.3 版）。导入脚本把它们复制进项目，跟代码一起进 GitHub（你的决定，见第 2 节）。

### 已定的 4 件事（2026-10-05 你确认的）

1. **游戏素材**：进 GitHub，之后你自己和作者交涉。
2. **天色**：随辩论进度从午后走到黄昏。
3. **镜头**：默认舞台全景；可以切到评委席，或者任意一个人物的第一人称。
4. **观众席**：先空着。

## 1. 要求和边界

### 用户原话（本次对话）

- 「因为我的世界这款游戏极其贴近现实世界，也有着极强的物理交互逻辑，所以我想以这个游戏的世界地图创作出场景来作为我们现在这个款项目的前端展示」
- 「这个游戏里面的各种东西可以直接用，等做出来之后我会拿成品和作者交涉」
- 「你要完全利用游戏里可用物，别单纯的用那些固定的几个大方块，做辩论室我看看」
- 「你给我设计方案就行，执行我会让其他agent」

此前定下、所有场景都适用的两条：

- 「视觉效果为速度让步……多个角色同时要输出文字或者同时移动的时候……拉长时间线去缓冲，但最终都会实现」
- 「效果展示也是要有逻辑的，然后尽可能符合现实工作/娱乐/辩论场景等现实逻辑」

### 由此定下的要求

- **R1 用游戏本身的东西**：场景是游戏世界里的一座建筑，不是“像游戏的风格”。方块、物件、人物模型、粒子、音效、字体都取自游戏文件。
- **R2 物件要丰富**：不能只用整块方块，要用上楼梯、台阶、活板门、栅栏、玻璃板、铁链、灯笼、讲台、钟、拉杆、红石灯、旗帜、告示牌、展示框和地图、画、书架、木桶、蜡烛、花盆、地毯等。完整清单见 3.5。
- **R3 物理和因果说得通**：
  - 东西要有依托，人不穿墙、不悬空；
  - 灯亮是因为有人扳了拉杆，钟响是因为有人敲了；
  - 光照按游戏规则传播。
- **R4 像真实的辩论赛**：
  - 主持掌控流程，负责亮灯、敲钟、宣布；
  - 辩手起立发言，立论和总结时对着评委，质询时对着被问的人；
  - 没轮到的人坐着听，看向说话的人。
- **R5 画面优先于速度**：动作排队，时间线可以拉长，但不丢动作；暂停时整个画面定格。
- **R6 先做辩论室**：这套做法和场景无关，以后办公室、教室、草地都能照搬，最后可以放进同一张地图，做成一座小镇。

### 不做的

- **不改辩论内容**：辩论的流程和发言内容不变。引擎只配合两处，见 5.3。
- **不替换现有场景**：2D 辩论室、辩论室 · 3D、辩论室 · 精模都保留，另外新增一个场景「辩论室 · 我的世界」。
- **不提交、不推送**：除非用户另说。

### 和其他工作的关系

本地工作区还有另一个会话没提交的 3D 舞台改动，涉及这些文件：

- `PixelStage3D.tsx` 和一批 `pixel*.ts`
- `SceneStage3D.tsx`、`DiscussionView.tsx`
- `types.ts`、`scenes.ts`、`styles.css`
- `engines/rational/engine.ts`

处理原则：

- 不要覆盖或回退这些改动；
- 新代码尽量放在新文件里，共用文件只加最少的接入点（见 7.3）；
- 最好等那批改动提交后，再在它之上开工。

### 导入脚本 `npm run mc:import`（`scripts/mc-import.mjs`）

**输入**：

- `MC_DIR`，默认 `F:\MC\.minecraft`；
- `MC_VERSION`，默认取 `versions` 里最新的一个。

脚本只读游戏目录，不改它。

**输出**到 `frontend/public/mc/`：

| 文件 | 内容 |
| --- | --- |
| `blocks.json` | 房间用到的方块状态，以及它们引用的模型（包括父模型） |
| `atlas.png` + `atlas.json` | 方块贴图拼图。每张贴图四周复制出 2 像素边，防止远处缩小时串色；带上 `.mcmeta` 里的动画帧信息 |
| `entity/`、`particle/`、`environment/`、`painting/`、`gui/` | 用到的实体贴图、粒子、天空贴图、画和提示框贴图 |
| `sounds/` | 用到的音效，按 `sounds.json` 从资源索引里取 |
| `font/mc.woff2` | 用游戏字体生成的网页字体：英文符号来自 `ascii.png` 等，中文来自 `unifont.zip` |
| `preview-debate.jpg` | 场景卡片的预览图，用当前默认室内机位截图生成；演示页 `?cover` 隐藏界面并按 3:2 取景 |
| `manifest.json` | 游戏版本、jar 的 SHA-1、生成时间和文件清单 |

**要求**：

- 重复运行，结果一致；
- 游戏版本变了就重新导入；
- 读不到某个文件时，报出具体缺的是哪一个，不要静默跳过。

### Git 和对外（用户已决定）

- 导入结果 `frontend/public/mc/` 跟代码一起进仓库，不写进 `.gitignore`。用户知道公开仓库里有游戏素材可能被要求下架，决定之后自己和作者交涉。

## 3. 房间

### 3.1 尺寸和坐标

- **方向**：坐标沿用游戏，+x 向东，+z 向南，+y 向上。舞台在北，观众席在南，默认镜头朝北看。
- **平面**：
  - 外墙范围 x 0–22、z 0–24；
  - 室内 x 1–21，中线是 x=11；室内 z 1–23。
- **高度**：
  - y=0 是地板层，观众席地面在 y=1；
  - 舞台（z 1–11）再垫一层，台面在 y=2，比观众席高一格，约 1 米，和真实礼堂的舞台差不多；
  - 横梁在 y=9，天花板在 y=10，再往上是屋顶。
- **记法**：下文的 (x, y, z) 都指方块格子；人和物件站在格子的底面上。
- **座位顺序**：场景 `debate` 的座位顺序是 0–2 正方、3–5 反方、6 主持。正方 0 号离主持最近，这里对应 z=5；反方同理。

### 3.6 光

**光源**：

- 吊挂和落地的灯笼，亮度 15；
- 桌上的蜡烛，3 根，亮度 9；
- 灯柱上的灯笼；
- 亮起的红石灯，亮度 15；
- 从窗户进来的天光。

**按游戏规则算**：

- **方块光**：从光源每走一格减 1，被不透光的整块方块挡住。
- **天光**：从天空往下不衰减，横向每格减 1；玻璃不挡光。
- **平滑光照**：每个顶点取周围四格的平均值，再加上环境光遮蔽。
- **面的明暗**：用游戏的固定系数，朝上 1.0，南北面 0.8，东西面 0.6，朝下 0.5。
- **亮度曲线**：等级 L 的亮度是 f / (4 − 3f)，其中 f = L / 15，再按游戏默认的 50% 亮度设置做伽马校正。方块光偏暖色，天光随时间变化。

**实现**：做法和游戏一样。

- 每个顶点存两个值：方块光和天光；
- 着色器查一张 16×16 的光照表；
- 天色变化时只改这张表，不重建网格；
- 红石灯开关时，只重算受影响的那一小块。

**最低亮度**：人坐着或站着的位置，下午和黄昏时的亮度都不低于 9，保证看得清脸。

### 3.7 搭建必须守的规矩（写成 `check-mc-room` 检查脚本）

1. **方块合法**：每个方块状态都在 26.3 的 `blockstates` 里，属性名和取值都合法，引用的模型和贴图都找得到。
2. **有依托**：
   - 吊挂的灯笼，上方是铁链或实心面；
   - 落地的灯笼、蜡烛、花盆和装在地上的拉杆，下方有实心顶面；地毯下方不能是空气；
   - 墙上的拉杆、墙上的旗帜、展示框和画，背后的方块有实心面；
   - 悬挂告示牌上方有方块；
   - 钟按 attachment 的取值有依托；
   - 门的上下两半配对，脚下有地。
3. **连接状态自动算**：栅栏、玻璃板、铁链这类会互相连接的方块，连接状态由脚本按邻居自动算，不手写。
4. **人的位置**：
   - 座位、发言站位、主持站位和走动路线上，人的碰撞箱（0.6×1.8×0.6，坐姿按坐着的高度算）不和任何方块的碰撞形状重叠；
   - 走动路线上每一步的高差不超过 0.6。
5. **两队镜像**：两队所在的区域（x 1–7 和 x 15–21，z 4–11，所有层），把 x 换成 22−x、把蓝换成红之后完全一致。主持区和观众席不要求镜像：灯柱对着钟、两侧挂的画，本来就不一样。
6. **镜头**：
   - 默认机位能同时看到 7 个人的头和肩，以及辩题板和三盏阶段灯；
   - 从镜头到每个人头部的射线不被方块挡住（桌面挡住下半身可以）。
7. **光照**：满足 3.6 的最低亮度。

## 4. 人物

### 4.1 皮肤：按人物外观生成

**做法**：每个人物按现有的外观数据（`PersonaVisual`：skin、hair、shirt、accent、hairStyle、extras）生成一张 64×64 的标准玩家皮肤，用宽手臂版（4 像素）。这样有两个好处：

- 内置人物和用户自建的人物都自动有形象；
- 颜色和他们在其他场景里的像素小人一致。

不用 Steve 等默认皮肤：七个人会撞脸，也对不上人物。

**贴图布局按游戏标准**：

| 部位 | 本体位置，尺寸 | 外层位置 |
| --- | --- | --- |
| 头 | (0, 0)，8×8×8 | 帽子层 (32, 0) |
| 身体 | (16, 16)，8×12×4 | 外套层 (16, 32) |
| 右臂 | (40, 16) | 右袖 (40, 32) |
| 左臂 | (32, 48) | 左袖 (48, 48) |
| 右腿 | (0, 16) | 右裤 (0, 32) |
| 左腿 | (16, 48) | 左裤 (0, 48) |

一个盒子（宽 w、高 h、深 d，起点 (u, v)）在贴图上这样展开：

- 顶 (u+d, v)，底 (u+d+w, v)；
- 右侧 (u, v+d)，正面 (u+d, v+d)，左侧 (u+d+w, v+d)，背面 (u+2d+w, v+d)。

拿 `entity/player/wide/steve.png` 核对各面朝向。

**外观怎么画到皮肤上**：

- **skin**：脸、脖子，以及手（手臂最下面 4 像素）。
- **hair**：头顶、后脑、两侧和前额刘海。10 种发型用头和帽子层的像素画出来：
  - `long`：在帽子层的后面和两侧往下画；
  - `bun`：在后脑的帽子层画发髻；
  - `cap`、`hood`、`beanie`：画在帽子层，cap 和 hood 用衣服颜色，beanie 用 accent；
  - `spiky`、`curly`：用帽子层边缘的锯齿和斑点表现。
- **shirt**：身体和上臂；**accent**：领口、扣子或腰带，一两条像素。
- **裤子和鞋**：按 shirt 自动取一个深色，鞋底两行再深一些。
- **extras**：
  - glasses 画在帽子层的眼睛位置，凸出一点，更像眼镜；
  - scarf 画在外套层，脖子一圈；
  - 其余（brows、sleepy、happy、grin、blush、sweat）是表情，见 4.4。

**脸**：脸是 8×8，第 4 行是眼睛（每只 2 像素：眼白加瞳孔），第 6 行是嘴。表情和说话时只换这 8×8 的脸，不重画整张皮肤。

### 4.2 模型、姿势和动作

以下是参考游戏原版的数值，可以按画面微调。

- **模型**：
  - 头 8×8×8，身体 8×12×4，手臂 4×12×4，腿 4×12×4。单位是像素，1 像素 = 1/16 格；
  - 外层放大：帽子层 0.5 像素，其他外层 0.25 像素；
  - 整体缩放 0.9375：人高约 1.87 格，眼睛高 1.62 格。
- **坐**：用游戏的骑乘坐姿。
  - 两腿前抬约 81°（xRot −1.4137），左右各外撇 18°（yRot ±π/10）；
  - 双臂前抬 36°（xRot −π/5）；
  - 屁股落在楼梯低的那半格上（坐面在 y+0.5），腿伸向桌前空出的那一格。
- **站起、坐下**：游戏里是瞬间完成的，这里用 0.3 秒过渡，避免画面跳变。
- **走**：
  - 每秒约 2.2 格，比游戏里的 4.3 格慢，像在会场里走路；
  - 手臂和腿按 cos(行进量 × 0.6662) 前后摆，摆幅随速度变化；
  - 每一步按地面材质播放脚步声。
- **挥手**（扳拉杆、敲钟、发言时强调）：用游戏原版的挥手动作，约 0.3 秒，身体带一点扭转。
- **待机**：手臂随呼吸轻微摆动。原版是 zRot 按 cos(t × 0.09) 变化 ±0.05 弧度，xRot 按 sin(t × 0.067) 变化 ±0.05，t 以 tick 计，每秒 20 tick。
- **看人**：
  - 头约 0.3 秒转向要看的目标；
  - 头和身体的夹角超过 50° 时，身体跟着转；
  - 没轮到的人看说话的人，说话的人看他说话的对象（见第 5 节）。
- **减少动态效果**：用户开启“减少动态效果”时，人物不摆动、不出粒子，站起和坐下直接切换。

### 4.3 名字牌、气泡、聊天栏

**总体做法**：

- 用 `DiscussionView` 里现有的座位层（那层 HTML 会跟着三维坐标移动），换成游戏的样式，不另做一套。
- 字体用 2 节导入的游戏字体（`font/mc.woff2`）。字号取 8 的整数倍，关掉字体平滑，保持点阵清晰。

**名字牌**：

- 在头顶上方，照游戏的样式：25% 透明度的黑底，字不加描边；
- 字色按队，用游戏的队伍颜色：正方蓝 `#5555FF`，反方红 `#FF5555`，主持金 `#FFAA00`。

**气泡**：

- 外观用游戏提示框的贴图（`gui/sprites/tooltip/background.png` 和 `frame.png`，按 `.mcmeta` 九宫格拉伸）；
- 第一行是名字（用队色），下面是正文，白字带 1 像素阴影；
- 显示时长沿用 `stageRules.readMs`；
- 同时最多两个。

**聊天栏**：

- 在舞台左下角，像游戏里那样一行一句：`<名字> 内容`，名字用队色；
- 每行半透明黑底，10 秒后淡出，最多 6 行；
- 用户自己说的话显示为 `<你> …`；
- 右侧面板的完整记录不变。

### 4.4 情绪

辩论引擎已经给每个人记着四种情绪（`engines/rational/moods.ts`）。按等级分两档表现：第一档换脸，第二档出粒子。

| 情绪 | 第一档（换脸） | 第二档（出粒子） |
| --- | --- | --- |
| 火气 | ≥3：眉毛压低 | ≥6：头顶冒怒气云（`angry`，就是村民生气时那种） |
| 压力 | ≥3：额头一滴汗 | ≥6：头侧往下滴水珠（`drip_hang` 接 `drip_fall`，用水的蓝色） |
| 信心 | ≥5：嘴角上扬 | ≥7：身边闪绿色星光（`glint`，就是村民高兴时那种） |
| 憋屈 | ≥3：脸红，嘴抿平 | ≥6：头顶冒几缕灰烟（`generic_*`，染成灰色） |

粒子只出现在正在说话的人和被质询的人身上，每 2–3 秒一小撮，免得满台冒东西。

## 5. 台上怎么动

### 5.1 规矩

- **变化由人做出来**：灯是有人扳了拉杆才亮的，钟是有人敲了才响的；人站起来，是因为轮到他发言。
- **动作排队**：每个人的动作排成一个队列，一个做完再做下一个，不跳过任何动作。
- **先站好再出字**：发言的气泡要等这个人站好、扳完拉杆才出现。
  - 为了让右侧面板的文字和台上同步，引擎在两处等舞台（见 5.3），最多等 4 秒，暂停期间不计时；
  - 超时就照常往下走，舞台随后补完动作，不丢。
- **同屏限制**：同时最多两个气泡。
- **暂停**：一切定格，包括动作、粒子、钟的摆动、天色、旗帜飘动；镜头仍然可以转。
- **舞台不显示时引擎不等**：比如切到 2D，或者页签在后台。

### 5.2 对照表

| 发生了什么（引擎事件） | 台上怎么动 | 声音 |
| --- | --- | --- |
| 场景打开 | 七人已就位：辩手坐在椅子上，主持站在讲台后。三盏阶段灯全灭，辩题板上显示辩题 | — |
| 新一轮开始（`round`） | 见表后说明 | 拉杆咔哒、钟声 |
| 辩手在准备（`status: thinking`） | 坐着低头看桌面，像在写提纲 | — |
| 开始发言（`status: speaking`） | 起身，向前一步站到桌后，扳下桌上的拉杆，桌前红石灯亮（开麦）。做完后通知引擎可以出字 | 脚步、拉杆咔哒 |
| 每一句（`message` 和 `message_update`） | 气泡和聊天栏出字。立论、总结时面朝评委席（镜头），偶尔挥手强调；质询时面朝被问的人 | — |
| 发言结束（`status: idle`） | 扳回拉杆，灯灭，退一步坐回椅子 | 拉杆咔哒、脚步 |
| 质询（这一句带 `targetId`） | 被问的人也起身站到自己的站位，两人隔着舞台面对面。被问的人回答时，同样扳自己桌上的拉杆 | — |
| 主持发言 | 先低头看讲台上的书、翻一页，再抬头面向评委席说 | 翻书 |
| 用户公开插话（说话人是用户） | 台上所有人转头看镜头（评委席上的你）约 2 秒。回答的人（默认是主持）面向镜头回答；如果是辩手回答，先起身 | — |
| 用户点名私聊（带 `targetId`、`private`） | 只有被点名的人看一眼镜头，不起身，别人没反应。他的回复在聊天栏里用游戏私聊的样式显示：灰色斜体，「某某 悄悄对你说：…」 | — |
| 情绪变化（`mind`） | 按 4.4 换脸、出粒子 | — |
| 暂停、继续 | 定格；继续时从定格处接着动 | — |
| 结束（`result`） | 主持连敲两下钟。全体起立，面朝评委席站一会儿（起立致意），然后坐下；三盏阶段灯保持亮着 | 两次钟声、经验球声 |
| 没有主持的场次 | 阶段灯和钟都不动（没人去扳、去敲），轮次只在界面上显示 | — |

**新一轮开始时**：

1. 主持转身面向北墙，抬头扳下这一阶段的拉杆，对应的灯亮起。
2. 转回来，走一步到钟旁敲一下。钟按游戏的方式摆 2.5 秒。
3. 回到讲台。全部做完后，通知引擎可以出字。

阶段灯：立论亮第 1 盏，交锋亮第 2 盏，总结亮第 3 盏。标准赛制有两轮交锋，第二轮交锋只敲钟，不再扳灯。

### 5.3 引擎要配合的两处

两处都在 `engines/rational/engine.ts`。这个文件现在有另一个会话没提交的改动，动之前先协调。

**1. 质询的句子带上 `targetId`**

- `speak()` 里已经有 `turn.target`，在 `display()` 生成消息时加上 `targetId: turn.target?.agentId` 即可。
- 加完之后核对两件事：
  - 右侧记录会显示成“甲 → 乙”，这正是想要的效果；
  - 整理公开记录和私聊的地方，不能把这种消息当成私聊。私聊靠 `private` 标记区分，这里不设这个标记。

**2. 等舞台**

- 创建引擎时，可以传入一个可选的 `stageGate`，提供两个异步方法：`round(index)` 和 `speech(agentId)`。
  - 引擎在“新一轮开始后”和“每段发言出第一句之前”各调用一次；
  - 最多等 4 秒，暂停期间不计时；
  - 没传 `stageGate` 就不等。
- 舞台组件做完起身、扳灯、敲钟后，通过 `onStageDone` 解开等待。
- 这和工作模式里“人先走到、再开口”是同一条规矩。

## 6. 镜头

**默认：舞台全景**

- 位置约在 (11, 7, 20.5)，看向 (11, 3, 6)；
- 竖直视角 50°，比游戏默认的 70° 窄，人显得更大；
- 七个人都在画面内。在 1544×868 的窗口里，坐着的人约 100 像素高；辩题板和阶段灯完整可见；
- 操作：拖动转头，滚轮小范围推拉，有“回到默认”按钮；
- 这些数值只是起点，用 3.7 第 6 条的检查和截图调定。

**评委席第一人称**

- 坐在评委桌正中，位置约 (11, 2.6, 15.3)；
- 视角 70°，和游戏默认一样；
- 这就是“你”的位置：用户插话时，台上的人看的就是这里。

**任意一个人物的第一人称**（用户 2026-10-05 加的）

- 镜头在这个人的眼睛位置，跟着他的头转：他看谁，你就看谁；
- 拖动可以自己看，松手后慢慢回到跟着他看；
- 看不到他自己的头和名字牌，他说的话显示在画面下方。

**切换**：舞台右上角放一组视角按钮：全景、评委席、人物视角（可以选 7 个人中的任意一个）。细节见 06 执行手册 6.2。

**以后可加**（不在第一版）：

- 镜头跟拍说话的人；
- 用 WASD 在礼堂里走动：按方块碰撞箱计算，不能穿墙；0.6 格以内的台阶自动迈上去。

## 7. 代码怎么组织

### 7.1 渲染要点（three.js，项目里已有 0.186）

**方块模型读取器**：自己写一个，读 26.3 的 `blockstates` 和 `models`。要支持：

- **variants**：按属性串匹配；值是数组时按权重选，用坐标做种子，保证每次结果一样。
- **multipart**：`when` 条件支持 OR、AND 和 `a|b` 写法。
- **模型继承**：`parent` 继承，`#纹理变量` 解析。
- **元素**：from/to；rotation（单轴 ±22.5° 或 ±45°，支持 `rescale`）；各面 uv（缺省时按位置算）；面旋转；`cullface`；`tintindex`；`shade`。
- **方块状态旋转**：方块状态里的 x/y 旋转和 `uvlock`。

可以对照开源实现核对细节（比如 misode 的 deepslate），但不要直接依赖它：它用自己的 WebGL 渲染器，和我们的 three.js 场景、人物、镜头合不到一起。

**合并网格**：

- 整个房间合成几块大网格；
- 被相邻实心整块方块挡住的面不画（`cullface`）；
- 按贴图透明度分三遍画：
  - 不透明；
  - 镂空：灯笼、铁链、活板门、树叶、玻璃板，用 alpha 测试；
  - 半透明：如果用到染色玻璃。

**着色**：

- 自定义着色器，读拼图贴图、16×16 光照表，以及每个顶点的方块光、天光、面系数和环境光遮蔽；
- 动画贴图（灯笼等）按 `.mcmeta` 里的帧时间换帧。

**染色**：带 `tintindex` 的草和树叶，用固定的平原群系颜色：草 `#91BD59`，橡树叶 `#77AB2F`，白桦叶 `#80A755`。

**要用代码画的东西**（游戏里这些也是代码画的）：

- 钟身，含摆动；
- 旗帜：旗杆、横杆、旗面，图案按染料颜色叠加，轻微飘动；
- 讲台上的书，含翻页动画；
- 展示框里的地图，也就是辩题板的画布；
- 画：正面用画布，背面用 `painting/back.png`；
- 告示牌上的字。

**人物**：玩家模型按 4.1 和 4.2 实现。每人一张皮肤画布，换表情只改脸那 8×8。

**粒子**：小方片，始终朝向镜头，按种类分别给上升、飘落、闪烁的运动。

**天空**：

- 天色随时间渐变，太阳沿弧线移动；
- 云层平铺，缓慢移动；
- 远处按天空色起雾，像游戏的视距雾。

**性能**：

- 一个房间加一圈室外，方块面数在几万以内；
- 渲染批次控制在 100 以内；
- 页签在后台时停止渲染。

### 7.4 舞台组件的接口

回调和 `PixelStage3D` 是同一套，另外多传几样状态。

```ts
interface McStageProps {
  scene: SceneDef;                                   // scene.mcStage === 'debate'
  cast: { id: string; seatIndex: number; role: 'pro' | 'con' | 'host'; name: string; visual: PersonaVisual }[];
  states: Record<string, AgentState>;                // 来自 status 事件
  speech?: { agentId: string; targetId?: string };   // 正在说的人和说话对象；正文仍由 HTML 层显示
  round: { index: number; total: number; label: string };
  moods: Record<string, Record<string, number>>;     // 来自 mind 事件
  userCue?: { at: number; targetId?: string };       // 用户刚说了话
  finished: boolean;
  paused: boolean;
  soundOn: boolean;
  onLoaded(error?: string): void;
  onSeatPositions(positions: Seat[]): void;          // 每人头顶名字牌的位置（舞台百分比），给 HTML 层用
  onStageView(view: StageView): void;
  onStageDone(kind: 'round' | 'speech', agentId?: string): void;  // 解开 5.3 的等待
}
```

## 8. 验收

### 机器检查

- `npm run test:mc-room`：3.7 的规矩全部通过。
- `npm run test:mc-stage`：用假时钟模拟一场快辩（3 轮），检查以下几点：
  - 开口前已经站好、扳了灯；
  - 灯亮当且仅当这个人在说话；
  - 新一轮的第一句出现在敲钟之后；
  - 同时最多两个气泡；
  - 暂停期间没有任何状态变化；
  - 所有动作最终都做完；
  - 等满 4 秒后引擎照常往下走，动作随后补上。
- 前端 `tsc` 和 `npm run build` 都通过。

### 看画面

在真实页面上截图，逐张查看，必要时放大局部。

| 时刻 | 要看什么 |
| --- | --- |
| 默认机位全景 | 七人就位；没有缺贴图（游戏的紫黑格子）、闪烁或接缝杂色；灯笼、铁链、活板门、玻璃板的镂空正确；旗帜的颜色和图案对；吊灯不挡辩题板；整体是暖色的室内光 |
| 辩手发言 | 站在桌后；桌前的灯亮着，拉杆是扳下的；气泡在头顶；聊天栏里有这一句 |
| 质询 | 两人都站着，面对面 |

| 用户插话 | 公开插话时所有人看向镜头；点名私聊时只有被点名的那个人看镜头，聊天栏里是灰色斜体的悄悄话 |

| 坐姿 | 腿不穿进桌子 |
| 其他 | 评委席视角和人物第一人称视角都正常；从窗户能看到室外；黄昏时人和字都看得清；名字牌颜色按队分；七个人的皮肤颜色和他们在其他场景里一致 |

### 跑一场真的

用真实模型跑一场快辩，从开始到出结果，记下各事件的时间。要求：

- 每次发言前的动作都做了；
- 台上和右侧面板的错位不超过 4 秒；
- 结束时全体起立。

### 性能和异常

- 1544×868 的窗口下不低于 55 帧；素材已导入时，首次加载在 3 秒内。
- 删掉 `public/mc/` 后：
  - 场景卡片隐藏或灰掉，并提示导入；
  - 已在这个场景里的会话退回 2D；
  - 控制台没有报错。
- 关掉音效后，一点声音都没有。

### 在游戏里对照（可选，推荐）

用 `mc-export` 导出，在 26.3 的创造模式里执行，用同一机位截图，和网页对比：方块、朝向、依托都要一致。这一步的成果也正好可以拿去和作者交涉。
