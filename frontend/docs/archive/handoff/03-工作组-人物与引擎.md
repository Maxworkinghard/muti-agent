# 工作组：需要提交的内容（工作 · 创造项目模式）

> 历史快照（2026-10-09 已标记）：正文只记录当时状态、计划与判断，不作为当前执行指令。当前入口/架构见根目录 [ARCHITECTURE.md](../../../../ARCHITECTURE.md)，工程与视觉验收见 [VERIFY.md](../../../../VERIFY.md)，资料状态见 [文档索引](../../README.md)。历史“通过/可接受”、分支和待办不自动构成当前事实或用户确认。

> 现状：工作引擎已有 13 个人物、四轮流程（立项派活 → 分头干活 → 互相评审 → 定稿交付）和台上调度。下面七项各自怎么做的，见[工作引擎说明](../../../src/engines/product/README.md)。以下保留给工作组的接口约定，事实部分已按现状更新。

仓库：https://github.com/Maxworkinghard/muti-agent，前端在 `frontend/`。

## 一、人物

每个人物一个 JSON 文件，放在 `frontend/personas/product/`，数量和内容由你们决定。前端启动时自动读取，不用改代码；文件按路径排序，文件名前面加数字可以决定先后。

人格资料包协议 v1.0 已支持 `product`；前端同时接受协议格式和简化格式。现有工作人物使用简化格式，字段与 `frontend/src/types.ts` 里的 `Persona` 一致：

| 字段 | 包含 |
|---|---|
| id / name | 唯一标识（小写字母开头，只含小写字母、数字和短横线）/ 名字 |
| modes | 适用模式，写 `["product"]` |
| identity | 一句话身份，例如“需求拆解师 · 把一句话拆成能开工的积木” |
| knowledge | 擅长的领域，字符串数组 |
| thinking / values | 思考方式 / 价值观 |
| personalities | 可选的性格或工作方式，每项含 id、label、behavior、style，可选 opener（口头禅） |
| defaultPersonalityId | 默认选中的一项 |
| boundaries | 底线，字符串数组 |
| visual | 像素形象：skin、hair、shirt、accent，可选 hairStyle、extras；或者用 image 放头像图片 |

参考样例：`frontend/personas/product/` 里现有的 13 个人物（原有 5 个，后来补了 8 个），例如 `01-ji-mu.json`。`_说明` 这类下划线开头的字段只是备注，前端不读。

如果需要额外字段（例如工作能力），先加到 `src/types.ts` 的 `Persona` 里，再在 `src/data/personas.ts` 的 `checkPersona` 里读出来，引擎就能从 `participant.persona` 拿到。

## 二、引擎需要包含的部分（具体怎么做由你们决定）

引擎就是在座人物讨论问题、解决问题的整套过程。提交时需要包含以下部分，并附一份简短说明（放在引擎目录下的 `README.md`），写清楚每一部分你们是怎么做的：

1. **讨论流程**：一共几轮（轮次名要和前端一致），每一轮的目标是什么。比如第一轮各自亮出观点，第二轮回应别人的观点。
2. **发言顺序**：每一轮谁先说、谁后说，一个人能不能连续说，要不要插嘴。
3. **每个人能看到什么**：发言前能读到哪些内容，比如前面所有人的发言、只看上一个人的发言，或者只看对方的发言；对话历史保留多长。
4. **人物怎么体现**：人物文件里的身份、知识、思想、性格、说话方式、底线，怎样影响他的发言。
5. **用户插话**：用户发消息或向某个人提问时，由谁回应、什么时候回应，回应完怎样回到原来的流程。点成员的私聊只让被点的人看到——不进公开记录、不占公开发言位，别按公开插话处理（其他模式都是这么做的）。
6. **结束与结论**：什么时候结束，最后的共识、分歧、待解决问题、建议是怎么得出来的。
7. **异常处理**：用户点击停止，或者 AI 调用出错、超时，这时候怎么办。

以上内容通过下面的接口接进前端。

## 三、引擎接口

代码放在 `frontend/src/engines/product/`：`index.ts` 导出下面这个对象，`registry.ts` 按模式取用；`config.ts` 放可调参数的默认值，开讨论时会复制到 `config.engineOptions`。

```ts
{ mode: 'product', name, owner, create, defaults }
```

现在 `create` 是 `createBackendEngine`：流程在后端的 `server/work.ts`（由 `server/session.ts` 的会话运行），每位成员是一段直接调用模型的对话。换成你们自己的流程时，把 `create` 换成自己的实现即可；在浏览器里调用模型用 `src/llm/client.ts`（写法见 `src/engines/README.md` 的「调用 AI」），不要把 Key 写进前端代码。

`create()` 返回：

```ts
{
  start(config: SessionConfig, emit: (e: EngineEvent) => void): void;
  sendUserMessage(input: { text: string; targetAgentId?: string }): void;
  pause(): void;
  resume(): void;
  stop(): void;
}
```

引擎的输入和输出格式如下，完整定义见 `src/types.ts`，这个文件不要修改。

**输入** `SessionConfig`：`{ sessionId, mode, sceneId, theme:{title, brief}, maxRounds, participants[], engineOptions, createdAt }`

讨论页不会自动开始。用户先在输入框里写下想讨论的内容（也可以只说一句“开始吧”），发送后前端才调用 `start()`。这段话放在 `theme.brief` 里传给引擎，讨论要围绕它展开：没填主题时它就是要讨论的问题，填了主题时它是补充说明。前端已经把它作为第 0 轮的用户消息显示出来，引擎不需要再回显。

participant 的格式：`{ agentId, seatIndex, color, personalityId, persona, side?, isLead? }`。`personalityId` 是用户在选人物页选的性格；用协议格式提交的人物，`persona.protocol` 就是文件里 `persona` 的原文。

工作模式下，participant 带有 `isLead`，标记负责人；`result` 需要包含 `deliverables`。

**输出** 通过 `emit` 发出的事件：

| 事件 | 格式 |
|---|---|
| session | `{type:'session', state:'running'\|'paused'\|'finished'\|'stopped'}` |
| round | `{type:'round', round, label}` |
| status | `{type:'status', agentId, state:'idle'\|'thinking'\|'speaking'\|'working'\|'done', action}` |
| message | `{type:'message', message:{ id, round, speakerId, text, kind:'speech'\|'user'\|'reply'\|'system'\|'task'\|'notice'\|'react', targetId?, private?, tag?, quote?, cut?, doc?, at }}`：工作模式里当面跟同事说话时 `targetId` 是那位同事，`private` 标记私聊，`tag` 是环节（站会、第一版、评审……），`doc` 标记交出来的文件（第一版） |
| message_update | `{type:'message_update', id, text}`：流式发言时，按同一个 id 更新全文 |
| task | `{type:'task', task:{ id, title, from, to, status:'assigned'\|'handoff'\|'review'\|'done' }}`：派活、交接、送审、交付 |
| move | `{type:'move', agentId, to}`：离开或回到工位，`to` 是 `desk`、`huddle`（站会）、`meeting`（会议室）或同事的 agentId（走到他工位旁） |
| result | `{type:'result', result:{ consensus[], disagreements[], openQuestions[], suggestions[], deliverables?[], summary? }}` |
| theme | `{type:'theme', title}`：没填主题时，按用户的第一句话起的主题 |
| error | `{type:'error', id, agentId?, message, retry?}`：前端显示错误卡片，给了 retry 时显示“重试”按钮 |

`speakerId` 填发言人的 agentId，用户发的消息填 `'user'`，引擎的提示填 `'system'`（`kind:'notice'`）。用户对某个成员说的话，`targetId` 填该成员的 agentId；回应用户的消息，`targetId` 填 `'user'`。
